# AI文本检测

本目录负责模块定义、独立场景页面、业务服务和类型草案。

| 场景 | 页面文件 | 接口 |
| --- | --- | --- |
| AI论文与学术稿件检测 | `pages/academic.js` | `POST /api/v1/text/academic` |
| AI新闻稿与投稿内容检测 | `pages/news.js` | `POST /api/v1/text/news` |
| AI网文与小说内容检测 | `pages/novel.js` | `POST /api/v1/text/novel` |

新闻与小说页面已有前端工作台；论文页面仍保留框架入口。两个接口均已接入EGTE句级AI检测，新闻接口另有三审三校，小说接口另有重复/水稿检测；其余检测场景继续抛出`NOT_IMPLEMENTED`，不生成模拟结果。设置`TEXT_MODEL_PROVIDER=deepseek`与服务端Key后默认调用`deepseek-v4-pro`；凭据不进入浏览器，未配置时返回`MODEL_NOT_CONFIGURED`。

项目根目录`.env`可填写`TEXT_MODEL_API_KEY`及`EGTE_API_URL`（默认 `http://127.0.0.1:8011`）。加载器只读取`TEXT_MODEL_*`和`EGTE_*`字段，且不会覆盖部署环境已经设置的变量。Node服务向该完整地址发送`POST`请求，请求体为`{"classifier":"cred|raid","segments":[{"segmentId":"...","text":"..."}]}`；响应可直接返回数组，或放在`results`、`data`、`data.results`字段中。每项应返回`segmentId`、`aiScore`和`predictedLabel`，同时兼容对应的snake_case字段；仅返回分数时会以`0.5`推导原始二分类标签，最终人工/疑似AI/AI标签仍由平台配置的聚合阈值计算。

浏览器按句切分AI检测材料并保留UTF-16字符区间，少于20字符的句子与同段相邻句组成最多两句的评分片段。服务端重新分句并校验连续编号、段落边界、完整覆盖和原文一致性后，批量提交给独立EGTE HTTP服务评分。中文使用C-ReD，英文使用RAID；合并得分只属于两句整体，两句合并后仍过短或失败的片段返回空分数和原因。新闻正文另由服务端按原始段落自动切窗，初审、复审、终审、一校、二校和三校分别执行并返回目标、检查项、覆盖范围与问题，问题均附连续原文；`proofreading.issues`保留跨阶段去重汇总用于兼容旧调用方。小说以章节为强边界，重复/水稿问题附一段或多段原文；同次提交多章时可识别跨章完全重复。当前没有持久化作品索引，因此一次只提交一章时不具备跨章记忆。

小说章节可从横向单选栏选择刺猬猫、飞卢小说网、纵横中文网、番茄小说、起点中文网或未知平台，章节链接会按官方域名自动匹配。已知平台随章节进入检测请求；AI结果和重复/水稿结果都会返回本次涉及平台的官方规则，未知平台不返回规则链接。AI结果优先使用平台公开的AI专项规则，没有专项规则时回退到通用创作者公约；重复/水稿结果始终使用原创、重复内容、无意义填充和恶意水文等通用创作规则。番茄两个结果页因此使用不同链接。

新闻和小说检测的顶层`status`只表示所选服务是否执行完成；网页来源完整性不足和个别AI片段无法评分分别保留在`coverage`与`aiRisk.status`中，不再把已有可展示结果的整次请求显示为“部分完成”。只有某个检测服务确实未执行时才返回`partial`，并通过`incompleteServices`逐项给出服务名称和原因；前端同步展示缺项说明。AI摘要会明确统计无法评分片段数。

句级AI结果会进一步按有效字符数加权，输出段落分数、全文分数和人工/AI/疑似AI字数占比；连续的AI或疑似AI句子合并为可回查原文的片段，且不跨小说章节。默认分数阈值为人工 `<0.5`、疑似AI `>=0.5 且 <0.8`、AI `>=0.8`；人工或AI相关内容占已评分字数达到 `60%` 时输出“人工为主”或“AI为主”，否则输出“人机混写”。模型版本、阈值、UTF-16原文位置、加权分数和标签随每个聚合片段一起保存，可通过 `EGTE_MODEL_VERSION`、`EGTE_HUMAN_MAX_SCORE`、`EGTE_AI_MIN_SCORE` 和 `EGTE_DOMINANCE_MIN_RATIO` 覆盖默认配置。

新闻和小说均将原JSON导出替换为两份独立的A4 PDF打印报告：AI内容分析单独一份，新闻三审三校或小说重复/水稿单独一份。AI报告不再逐段输出段落排行，而用一条多色横条汇总全文人工、疑似AI、AI和无法评分构成；AI、疑似AI及无法评分片段全部展开，普通人工片段不逐条导出。点击对应按钮后打开打印预览，使用浏览器“另存为 PDF”分别保存两个文件。

新闻页面另有独立的`POST /api/v1/text/news/import`预处理接口，优先从JSON-LD新闻结构、Open Graph和语义正文容器提取公开标题、正文、作者与发布时间。除结构清晰的公开HTML外，当前适配新华网、央视网、中新网、凤凰网和澎湃新闻的已验证正文容器。结果先进入可编辑预览，用户确认后才作为链接来源的稿件材料；链接改变后必须重新提取。该提取不执行页面脚本，也不绕过登录、付费、验证码或WAF；视频、直播、专题、登录验证和仅客户端渲染页面不在保证范围内。

小说页面另有独立的`POST /api/v1/text/novel/import`预处理接口，用于公开单章节网页的安全获取，以及作品名称、章节标题和正文的提取、预览与确认。当前成功适配刺猬猫公开MIP/WAP章节、飞卢公开免费章节、纵横公开免费章节和结构清晰的公开HTML；目录页、登录/付费页、起点WAF及番茄动态字体正文只返回对应说明。作品名称无法可靠识别时留空供用户补充；用户确认导入后，非空的预览名称会复写作品名称。该接口不执行检测，确认后的正文与来源元数据才会进入现有章节和检测请求。

各场景继续按工作包开发；修改同一`service.js`或公共定义前先与同模块成员对齐。完整分工见[团队开发](../../../docs/TEAM_DEVELOPMENT.md)。
