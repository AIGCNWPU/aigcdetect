# AI文本检测

本目录负责模块定义、独立场景页面、业务服务和类型草案。

| 场景 | 页面文件 | 接口 |
| --- | --- | --- |
| AI论文与学术稿件检测 | `pages/academic.js` | `POST /api/v1/text/academic` |
| AI新闻稿与投稿内容检测 | `pages/news.js` | `POST /api/v1/text/news` |
| AI网文与小说内容检测 | `pages/novel.js` | `POST /api/v1/text/novel` |

新闻与小说页面已有前端工作台；论文页面仍保留框架入口。10个检测场景服务继续抛出`NOT_IMPLEMENTED`，不生成模拟结果。

新闻页面另有独立的`POST /api/v1/text/news/import`预处理接口，优先从JSON-LD新闻结构、Open Graph和语义正文容器提取公开标题、正文、作者与发布时间。除结构清晰的公开HTML外，当前适配新华网、央视网、中新网、凤凰网和澎湃新闻的已验证正文容器。结果先进入可编辑预览，用户确认后才作为链接来源的稿件材料；链接改变后必须重新提取。该提取不执行页面脚本，也不绕过登录、付费、验证码或WAF；视频、直播、专题、登录验证和仅客户端渲染页面不在保证范围内。

小说页面另有独立的`POST /api/v1/text/novel/import`预处理接口，用于公开单章节网页的安全获取，以及作品名称、章节标题和正文的提取、预览与确认。当前成功适配刺猬猫公开MIP/WAP章节、飞卢公开免费章节、纵横公开免费章节和结构清晰的公开HTML；目录页、登录/付费页、起点WAF及番茄动态字体正文只返回对应说明。作品名称无法可靠识别时留空供用户补充；用户确认导入后，非空的预览名称会复写作品名称。该接口不执行检测，确认后的正文与来源元数据才会进入现有章节和检测请求。

各场景继续按工作包开发；修改同一`service.js`或公共定义前先与同模块成员对齐。完整分工见[团队开发](../../../docs/TEAM_DEVELOPMENT.md)。
