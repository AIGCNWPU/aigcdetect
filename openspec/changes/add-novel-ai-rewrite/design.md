# Design

## Context

见[proposal](proposal.md)。小说页面目前将章节和当前检测结果保存在页面内存中；AI结果已经包含章节ID、字符区间、风险标签、模型版本与阈值。服务端已有小说质量分析的模型客户端和严格原文证据回查，但没有小说改写任务。论文降重依赖独立8010服务且固定为学术风格，因此只复用交互理念，不直接复用其提示词或后端。

## Goals / Non-Goals

**Goals:**

- 以现有小说AI风险片段为唯一自动改写范围，生成可回指原文的替换建议。
- 在覆盖原稿之前提供逐条与批量选择，并以不可变章节版本保存结果。
- 在当前页面保留版本、检测快照和报告生成依据，刷新后清空。
- 复用现有AI检测与PDF报告能力完成修改前后对比，并提供纯正文下载。

**Non-Goals:**

- 不提供服务端作品库、账号同步、跨浏览器同步或多人协作。
- 不保证检测分数下降，不针对第三方检测器做无限循环优化。
- 第一版只下载UTF-8 TXT，不承诺保留上传DOC/DOCX的字体、分页和其他版式。

## Decisions

### 1. 在现有小说接口增加独立 rewrite action

`POST /api/v1/text/novel`继续作为场景入口，`action: "rewrite"`与现有`action: "analyze"`分流。改写请求携带作品名、章节版本、正文哈希和风险片段；服务端验证每个片段的章节、范围和连续原文后才调用模型。这样复用现有服务端凭据隔离、错误格式和部署入口，避免依赖仓库中缺少实现的论文8010 humanize服务。

替代方案是新增独立URL或复用论文`style=academic`接口；前者增加路由与代理面，后者会产生学术腔并缺少章节契约，均不采用。

### 2. 模型只返回片段ID和候选文本

模型任务`novel_rewrite`接收带稳定ID、原文和有限上下文的风险片段，只返回`fragmentId`、`after`和`reason`。字符区间以服务端已验证的请求为准，模型不得自行生成位置。服务端拒绝缺失ID、原文不匹配、空文本、重复ID和明显越界输出，并返回可独立接受的建议。

### 3. 客户端按父版本坐标合成新版本

所有建议绑定`parentVersionId`和`contentHash`。预览及最终生成时按`start`降序替换，先检查区间不重叠且`content.slice(start,end)===before`。批量接受只切换建议状态；“生成修改后版本”才创建不可变版本。手动编辑后校验当前正文与父版本；同一建议批次只能生成一次，生成操作防止并发点击，多章全部验证后再一次性更新。

### 4. 使用页面内存保存本次历史

以页面实例内的版本化JSON保存作品、章节版本、建议批次和检测快照；PDF由本次结果快照按需生成。刷新或重新打开页面后记录清空，与检测页面保持一致；初始化时仅移除旧版改写专用存储键，不清理其他业务数据。

记录不写入localStorage或sessionStorage。异步校验和保存不替换当前正在操作的对象引用，避免并发保存导致版本或建议丢失。

### 5. 检测和报告快照按版本保存

每次成功检测按提交时的章节快照、`versionId`或稿次以及内容哈希绑定结果；正文相同的不同稿次也各自保留检测记录。旧快照不可变；修改版创建后状态为待检测。复检继续调用现有`analyze`动作，并将返回结果附到修改版。报告按钮使用所选版本的快照生成，避免当前结果覆盖旧报告。

### 6. 下载正文与报告分离

修改后章节下载为UTF-8 TXT，仅包含完整章节正文并保留换行；文件名为`作品名-章节名-改写版-vN.txt`。检测报告仍使用现有PDF导出并绑定版本。这样可直接获得干净成稿，同时避免把检测元数据混入正文。

## Risks / Trade-offs

- [页面内存有限，长篇多版本可能超过限制] → 按章节限制历史数量和总序列化大小，写入失败时保留内存状态并明确提示，不自动删除关键版本。
- [模型改写可能改变人物口吻或事实] → 提示词施加小说约束，逐条展示前后文，默认不接受，用户确认后才生成版本。
- [多个建议区间冲突导致错误替换] → 服务端和客户端双重验证区间，冲突项不可批量接受，替换按坐标逆序执行。
- [只优化同一检测器导致过拟合] → UI称“降低AI风险建议”而非保证降率，修改后必须独立复检并展示模型版本与覆盖差异。
- [用户已有未提交的小说页面修改] → 改动集中到新模块并以小范围接线方式修改`novel.js`，保留工作区现有未提交变更。

## Migration Plan

新版初始化时清除旧版改写专用localStorage键，不读取历史正文。首次成功检测创建当前稿次快照；本次记录随页面刷新释放，不涉及服务端数据迁移。
