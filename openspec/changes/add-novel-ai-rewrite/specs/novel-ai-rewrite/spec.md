# Spec Delta

## Purpose

为小说AI检测后的风险片段提供可核对、可选择、可撤销的小说化改写，并在当前浏览器保存原版和修改版的正文、检测结果与报告依据，支持复检对比和下载修改后章节。

## ADDED Requirements

### Requirement: 检测后生成小说改写建议
系统 SHALL 只在章节存在成功的AI检测结果且正文版本仍与该结果匹配时，为AI或疑似AI片段生成小说风格改写建议；建议 MUST 保留情节事实、人物名称、叙事视角、对白关系和章节顺序，不得宣称保证降低任何检测器分数。

#### Scenario: 为当前版本生成建议
- **WHEN** 用户对已完成AI检测且未修改的一个或多个章节选择降低AI风险
- **THEN** 系统按章节和原文片段生成带修改前、修改后及说明的建议，并保持建议与原章节版本及原文位置关联

#### Scenario: 检测结果已经过期
- **WHEN** 章节正文或版本在检测后发生变化
- **THEN** 系统拒绝使用旧检测结果生成或应用建议，保留现有正文并提示先重新检测

#### Scenario: 改写服务失败
- **WHEN** 模型未配置、请求失败或返回内容不能回指原文
- **THEN** 系统显示真实失败状态，不生成替换项、不修改章节，也不丢失原检测结果

### Requirement: 逐条与批量接受
系统 SHALL 允许用户逐条接受、拒绝或恢复改写建议，并提供“接受本章全部”和“接受全部选中章节”；批量接受 MUST 仅更新建议选择状态，直到用户明确生成修改后版本才创建新正文。

#### Scenario: 逐条接受建议
- **WHEN** 用户接受或拒绝单条建议
- **THEN** 系统即时更新修改后预览和已接受数量，但不覆盖原章节版本

#### Scenario: 一键接受本章全部
- **WHEN** 用户点击“接受本章全部”
- **THEN** 系统选择该章所有仍有效且互不冲突的建议，并明确显示选择数量

#### Scenario: 一键接受全部选中章节
- **WHEN** 用户对多章改写结果点击“接受全部选中章节”
- **THEN** 系统选择这些章节内所有有效且互不冲突的建议，并按章显示选择数量；无效或冲突建议保持未接受并说明原因

### Requirement: 浏览器内章节版本与旧结果保留
系统 MUST 将原章节和每次确认生成的修改后章节保存为不可变版本，并在当前页面内存保存版本正文、父版本、内容哈希、接受的建议以及对应检测结果；本次页面内旧版本结果和报告依据 MUST 保留可查看和对比，刷新或重新进入页面后 MUST 清空。

#### Scenario: 生成修改后版本
- **WHEN** 用户至少接受一条有效建议并点击生成修改后版本
- **THEN** 系统从当前父版本按原文逆序应用替换，创建递增的新版本而不覆盖原版，并将新版本标记为待检测；同一建议批次 MUST 仅能生成一次

#### Scenario: 刷新后清空版本
- **WHEN** 用户刷新或重新打开小说页面
- **THEN** 系统 MUST 不恢复旧章节版本、建议选择或检测快照，并移除旧版改写功能专用持久记录

#### Scenario: 查看旧结果与报告
- **WHEN** 用户切换到任一旧章节版本
- **THEN** 系统展示该版本当时保存的检测结果，并可由其报告快照重新生成对应报告，不以新版本结果替换旧结果

### Requirement: 修改后复检与版本对比
系统 SHALL 允许修改后版本重新执行现有AI检测，并在相同模型信息可用时展示原版与修改版的分数、风险片段和覆盖范围变化；复检完成前 MUST 显示待检测，不得推断AI风险已经下降。

#### Scenario: 修改后版本尚未复检
- **WHEN** 用户创建修改后版本但尚未执行AI检测
- **THEN** 系统保留原版检测结果，并将修改版显示为待检测且不展示虚构的修改后分数

#### Scenario: 完成版本对比
- **WHEN** 修改后版本AI检测成功
- **THEN** 系统按提交时的版本ID或稿次和内容哈希绑定检测快照，正确展示第二、第三及后续稿次的检测结果；即使内容与旧稿相同也不得回绑旧稿，并保留各稿独立报告

### Requirement: 下载修改后章节
系统 SHALL 允许用户下载任一修改后章节版本的纯正文文件；文件 MUST 使用作品名、章节名和版本号构成可识别名称，且不得混入AI分数、审阅标记或系统提示。

#### Scenario: 下载修改后正文
- **WHEN** 用户在修改后版本点击下载章节
- **THEN** 系统下载包含该版本完整章节正文的UTF-8文本文件，并保持段落和对白换行

#### Scenario: 下载旧修改版本
- **WHEN** 用户切换到较早的修改版本并点击下载
- **THEN** 系统下载所选版本正文，不静默替换为当前最新版本

### Requirement: 浏览器存储边界与安全
系统 MUST 只在当前页面内存保存小说版本和检测快照，不写入浏览器持久存储，不保存服务端模型凭据，不把章节原文写入服务端日志。

#### Scenario: 页面历史容量不足
- **WHEN** 当前页面历史超过容量限制或历史快照校验失败
- **THEN** 系统保留当前内存中的原章节和操作状态，提示具体原因，不得声称历史快照已经保存成功

#### Scenario: 历史数据损坏
- **WHEN** 页面历史快照无法验证结构或内容哈希不匹配
- **THEN** 系统拒绝该快照并保留可用章节输入，不把损坏数据作为检测或改写依据
