## 前端阶段设计（2026-10-21）

本轮只实现浏览器端工作台，不宣称作品保存、文件解析、模型检测和报告存储已经可用。

- 页面分为“作品与章节”“章节检测”“作品报告”三个页签。用户可在本地草稿中添加、编辑、删除和勾选章节，单章和多章共用检测入口。
- 章节支持粘贴正文或选择文档。DOC/DOCX前端只记录文件信息，二进制上传和正文解析待公共文件服务接入。章节更新会增加本地版本并使旧结果失效。
- 页面通过`window.Veritas.api.invoke('/text/novel', payload)`调用现有入口。当前暂定`payload`包含`action`、`work`、`chapters`和`checks`；章节带本地标识、标题、版本及正文或文件信息，只用于前端联调。
- 页面暂定读取`status`、`aiRisk.summary/findings`和`quality.summary/findings`。AI生成风险与重复/水稿线索分别呈现，问题位置由服务端返回的章节和位置文本显示。
- 只有成功响应才更新章节状态、生成作品汇总并启用报告导出。501或其他失败显示真实错误，章节草稿不丢失；材料更新后禁止继续导出旧汇总。
- 响应式布局复用项目现有断点，未引入框架、运行时依赖、CDN或客户端密钥。

## 重复与水稿检测设计（2026-10-26）

- 章节是强边界；每章保留原始段落ID，最多40段或约8000字组成一个窗口，相邻窗口重叠2段。只有单个超长无换行段落才按完整句子组合虚拟段落。
- 模型只报告带连续原文证据的`repetition`或`padding`；服务端回查每个证据的章节、段落ID和`quote`，无法回指原文的结果丢弃。必要伏笔、合理强调、人物口头禅和文学修辞在提示中明确排除，降低水稿误报。
- 本地确定性检查先识别长度至少20字的完全重复段落。同一次请求提交多章时可输出双方章节与段落引用；只提交一章时`coverage.crossChapter`必须为`not-available`。
- 当前没有作品数据库或向量索引，因此不存在跨请求记忆。作品级历史段落指纹、向量召回、章节版本更新与删除传播作为后续任务，不在第一版中伪造。
- 模型配置与错误隔离复用新闻三审三校的服务端适配层；小说单章上限100000字、一次最多20章/300000字，分析请求JSON上限4 MiB。结果返回SHA-256内容哈希、章节/段落/窗口覆盖范围和导入完整性提示。
- `TEXT_MODEL_PROVIDER=deepseek`时复用DeepSeek官方Chat Completions与`deepseek-v4-pro`默认配置，启用JSON Output、thinking和`high`推理强度；真实Key只在服务端进程环境中提供。
- 本地服务自动加载项目根目录`.env`中的`TEXT_MODEL_*`字段，且不覆盖部署环境；`.env`由Git忽略，避免把真实Key提交到仓库。

## 句级EGTE检测与问题原文（2026-10-26）

- 每章由浏览器独立切句并生成UTF-16`start/end`，章节ID加入返回结果避免多章句号冲突。服务端逐章验证句子位置和原文一致性，中文选`cred`、英文选`raid`。
- 复用新闻场景的常驻`scripts/egte_worker.py`，同一个Node进程只维护一个Python桥接进程，分类器按需加载并复用；句子顺序评分，避免多份显存占用。
- 前端逐句显示`疑似AI`、`人工`或`无法评分`。未校准`aiScore`乘100后以百分比形式显示，但只称“AI类得分”并标记“非概率”；长句在固定最大高度的原文框内滚动，整组句级列表最高640px后纵向滚动，并可筛选全部句子或仅`predictedLabel=1`的疑似AI句子。
- 共享EGTE说明要求去除首尾空白后至少20字符且至少3个Falcon token。超过100字符的长句优先按软标点切分；不足30字符的短句优先与同段相邻句合并，小说中连续且各自仅含一句的短段也可成对合并。评分片段保持非重叠、最多两句且不超过100字符，服务端重新分句验证连续编号、完整覆盖、段落关系和原文区间。合并后仍不满足条件则不评分，合并得分只属于整个连续片段，不得拆给其中某一句或某一段。
- 新闻和小说共用的算法输入副本先做NFKC、空白折叠和危险不可见字符清除；纯文本本身保持为合法Markdown兼容内容。该副本不覆盖原文，因此展示、UTF-16位置与报告仍引用用户原文。
- 8012批量端点对413、422和500执行全请求共享预算的递归二分；批次级500拆分后若子批次成功，视为批量边界或瞬时故障，正常保留结果；稳定定位到单个500片段时仅将该片段标为无法评分，其余片段继续。若全部可评分片段都稳定触发500、隔离预算耗尽，或发生400契约错误、连接、超时、鉴权、限流及网关错误，仍作为服务级失败，避免掩盖算法整体故障。
- 重复/水稿结果保留`originalText`与全部`references[].quote`，前端逐段展示章节、段落和原文，跨章问题可直接对照两端证据。
- 重复/水稿问题列表采用最大高度和独立纵向滚动，避免大量问题撑高整个结果页。
- 模型结果校验的`receivedFindings/acceptedFindings/rejectedFindings`仅写入服务端`text_model_evidence_rejected`审计事件，并关联`requestId`与`scenario`。客户端只接收通过原文回查的重复/水稿线索，摘要和状态不暴露内部拒绝与校验过程；审计日志不包含章节原文、模型原始内容或凭据。合法JSON缺少`findings`数组仍按上游结构错误处理。
- 服务端项目与共享模型默认路径分别为`/home/wyt/projects/aigcdetect`和`/mnt/vos-6d37s2q0/users/yh/models/EGTE_CRED_RAID_20261023`；只读使用算法目录，运行配置放项目`.env`。

## 发布平台与创作者规则提示（2026-10-30）

- 章节表单使用点击展开的平台单选面板，折叠状态显示当前平台，选择后自动收起；固定选项为刺猬猫、飞卢小说网、纵横中文网、番茄小说、起点中文网、晋江文学城、17K小说网、咪咕文学和未知平台，不允许输入任意平台名称。已删除平台的历史值通过统一归一化回落到未知平台，不生成规则链接。
- 平台规则同时出现在AI内容分析和重复/水稿结果中。AI结果优先链接该平台公开的AI专项规则，没有专项规则时回退到通用创作者公约；重复/水稿结果始终链接原创、重复、无意义填充或恶意水文等通用规范。
- 顶层检测状态表示所选服务是否完成；来源完整性和句级可评分覆盖率由各自明细表达，不再把已正常返回的检测请求降为“部分完成”。
- 输入章节链接时按官方域名自动匹配平台，无法识别或链接无效时回落到未知平台；链接提取成功后以适配器返回的站点再次校准。手动选择结果随章节保存、编辑和检测请求传递。
- AI检测结果为本次选择的已知平台展示官方创作者协议、签约要求或内容治理规则；多章属于同一平台时只显示一次，未知平台不显示规则链接。
- 平台规则元数据集中维护通用规则和可选AI专项规则的官方HTTPS链接、摘要和核验日期。番茄配置两套规则，其他平台当前没有可确认适用于小说创作的AI专项页，AI结果回退使用其通用规则；不得把咪咕协议中的合成内容标识要求或通用原创义务扩写成全面禁止AI写作。
- 平台链接属于辅助核对信息，不参与AI分数和标签计算；页面明确提示以打开后的平台最新规则为准，报告保存本次返回的平台规则元数据。

## 章节链接导入设计（2026-10-23）

### Goals / Non-Goals

**Goals:**

- 在不依赖检测算法的情况下，完成“公开单章节链接 → 后端获取与提取 → 前端预览编辑 → 用户确认入章”的闭环。
- 对公开可读、部分可读、受限和提取失败给出可核对的状态，保留来源及覆盖范围，并阻止空正文进入章节列表。
- 将服务端请求限定在公网HTTP/HTTPS资源，限制重定向、时间和响应体大小。

**Non-Goals:**

- 不抓取目录页或整本作品，不自动翻页或批量导入，不绕过登录、付费、验证码、WAF、动态字体混淆或其他访问限制；只执行无需用户身份的公开页面脚本。
- 不在本轮实现AI检测算法、作品持久化、文件解析或正式报告；`POST /api/v1/text/novel`继续返回501。

### Decisions

1. **导入使用独立接口。** 新增`POST /api/v1/text/novel/import`，请求体为`{ "url": "https://..." }`，与现有检测入口分离。成功响应的`data`至少包含`sourceUrl`、`finalUrl`、`site`、`workTitle`、`title`、`content`、`extractionStatus`、`completeness`和`notice`；无法可靠识别作品名称时`workTitle`为空字符串，由用户在预览或主表单补充。`extractionStatus`使用`completed`或`partial`，`completeness`使用`complete`、`partial`或`unknown`。无可读正文时返回结构化错误，错误详情保留来源、`restricted`或`failed`状态、`unavailable`完整性及原因。
2. **使用服务端安全获取。** 前端不发起跨站请求。主服务使用`http`/`https`和DNS解析，首次请求及每次重定向均拒绝环回、私网、链路本地、保留地址及非HTTP(S)目标；请求固定到已校验的公网地址，最多跟随5次重定向，单次等待10秒，解压后的HTML上限2 MiB，只接受HTML或纯文本响应。常规提取失败时可调用独立8014 Playwright服务渲染公开页面。
3. **按站点适配并保留保守回退。** 成功适配刺猬猫公开MIP/WAP单章节页、飞卢新旧版公开章节页、纵横公开免费章节页、晋江移动公开章节页和17K公开章节页，从页面标题、作品元数据或作品链接提取作品名称，并从各站章节标题、正文段落容器及免费标记提取内容，同时移除段落水印、数字链接、站点尾注和导航。飞卢尾注按连续的求收藏/鲜花/票票/订阅/打赏或充值活动特征从尾部截断，不扫描或改写前方正文。结构清晰的公开HTML可通过小说元数据、页面标题、`article`、正文语义属性及常见章节正文容器进行保守提取；已撤销支持的站点在通用回退前明确拒绝，避免意外接管。无法可靠识别作品名称时留空，无法可靠识别章节标题或正文时失败，不以总字数单独判断完整性。
4. **访问限制不做绕过。** 刺猬猫跳转登录页标记为登录受限；起点返回202/WAF或验证码页时标记为访问受限；番茄页面检测到动态字体与大量私用区字符时标记为正文混淆。三者均不得把登录页、验证页或乱码作为正文，也不下载登录凭据、不还原反抓取字体；浏览器回退只执行公开脚本，不注入登录态。
5. **前端使用独立导入预览。** 章节表单增加链接输入、提取状态和可编辑预览。每次提取只更新预览区；点击“确认填入章节表单”后才复制作品名称、章节标题、正文和来源元数据。预览作品名称非空时，以这次确认的导入名称复写作品名称，不再要求第二次覆盖确认；表单已有章节标题或正文时仍显示明确覆盖确认。失败或只重新提取但未确认时不会清空或覆盖已有输入。
6. **章节保存确认后的材料。** 章节对象增加`source`，记录链接、站点、提取状态、完整性和提示。检测请求继续使用章节对象中的确认后正文，并携带`source`；部分或未知完整性的提示采用“仅检测已导入内容”。检测失败仍沿用现有真实501处理，不影响已导入章节。

### 动态页面浏览器回退（2026-11-09）

- 新闻与小说共用独立8014渲染协议，但各自仍使用原有正文提取器。正常静态章节不调用浏览器；明显脚本空壳页优先渲染，其他提取失败页在MinerU无结果后再尝试一次。
- 渲染结果继续经过站点适配器、通用章节规则和限制识别；必要时可把渲染后HTML交给8013 MinerU。成功结果记录`browser-rendered`或`browser-rendered-mineru`，失败时保留原章节导入错误。
- 浏览器不携带用户Cookie，阻止图片、媒体和字体，并对主文档与HTTP(S)子资源执行公网地址校验；限制并发、超时和渲染后HTML大小，不解决动态字体、登录、付费、验证码或WAF。

### 公开免费章节截图OCR实验（2026-11-12）

- 新增独立`probe:free-chapter`脚本，只处理调用者提供的一个公开单章节URL，不接入正式导入接口，也不自动沿目录、上一章或下一章继续抓取。
- 探测顺序为静态HTML规则、无凭据Playwright渲染、可见Canvas或当前视口截图、MinerU图片解析。每次保存诊断JSON和截图；识别成功时另存Markdown，明确标记OCR错字、漏段、界面噪声和完整性未知风险。
- 复用8014的公网地址、逐资源校验、无Cookie上下文、超时和并发限制；截图只在本地脚本进程中交给8013模块的MinerU命令，不新增可上传任意图片的HTTP接口。
- 页面仍停留“加载中”、没有足够识别文本，或出现登录、付费、验证码等限制时，不生成正式章节结论。出现限制提示但仍有足够可见OCR文本时只能标记为部分内容，供人工研究，不进入章节列表。

首批记录来自2026-10-23；晋江、飞卢新版、17K与咪咕回归记录更新于2026-11-12。同日根据产品范围决定撤销仅能提取作品页内嵌首章的两个平台适配。带`enter_from=page`的番茄样例仍在HTML与结构化数据中使用私用区字符，公开页面没有提供可直接读取的语义正文；新的起点免费章节样例仍返回HTTP 202验证页，咪咕入口返回HTTP 406验证页。因此不通过字体反向还原、验证码脚本或浏览器登录态规避限制。不代表同一站点所有章节永久保持相同行为；站点结构或权限变化时应返回失败而非降级为虚假成功。

### Risks / Trade-offs

- **站点结构会变化** → 适配器只在命中特征且正文可可靠读取时成功，测试保存脱敏HTML样例并覆盖结构变化后的失败行为。
- **DNS重绑定或恶意重定向造成SSRF** → 每一跳解析全部地址并拒绝任何非公网结果，请求通过已校验地址完成且保留原主机名用于Host和TLS校验。
- **页面声明完整但实际为试读** → 完整性结合站点适配器的结束标记、限制词和页面状态判断；缺少充分线索时返回`unknown`并提示人工确认。
- **通用提取误收导航或广告** → 优先使用站点适配器和语义正文容器，清理脚本、表单、导航及已知噪声；候选不明确时失败并建议粘贴正文。

## 检测完成状态语义（2026-10-31）

- 顶层`status`只表示所选检测服务是否执行并返回可展示结果。来源覆盖不足及个别AI片段无法评分保留在`coverage`、`aiRisk.status`、AI摘要和逐片段原因中，不将整次检测误标为部分完成。
- 只有检测项目确实未执行时才返回`partial`，同时通过`incompleteServices`返回服务名称与原因；前端顶部直接展示该缺项说明。

## 多章联合检测与分章结果（2026-11-10）

- 一次勾选的全部章节继续作为同一请求提交。重复与水稿检测先将所有章节段落组成统一窗口序列，段落携带`chapterId/chapter`，使短篇多章可以在同一模型窗口内比较，长篇仍按全书顺序进行有界重叠分窗。
- 服务端同时返回全书汇总和`chapterResults`。章节结果是对同一次全书检测结果的视图投影；跨章线索在所有被引用章节中可见，并始终保留完整证据，不触发二次模型调用。
- 前端在检测服务切换项下增加横向可滚动的“全文/章节”切换。AI与重复水稿两个服务共用当前章节范围，收到任一服务结果后立即按当前范围渲染。
- PDF仍按检测服务分别导出一个文件。多章报告保留全书指标，并按章节分节展示，避免把多个章节视觉上合并成单章。
- 若有效AI评分为零，聚合构成固定为“无法判定”；这属于可展示的真实检测结果，不伪造来源倾向。

- 作品报告拆分为AI内容分析PDF与重复/水稿检测PDF，均使用浏览器本地打印引擎和A4版式，不再下载JSON。
