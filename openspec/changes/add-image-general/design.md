# Design

## Context

范围见[proposal](proposal.md)，验收见[spec](specs/image-general/spec.md)。框架已经提供独立场景页与501空接口；业务待实现。

## Goals / Non-Goals

交付真实整图来源检测及可复用结果，优先复现模型和后端，再接入页面。不重新训练，不承诺未经测试的精度；本工作包不承担票据文字框定位或身份真实性判断。

## Decisions

负责人：③ 吕佳文。负责2.1单张与批量图片AI来源检测，提供可供④按材料版本引用的结果；售后局部篡改、商品核对和案件汇总归④，不以完成证件票据流程为调用前提。

- 页面：`src/modules/image/pages/general.js`，目前不创建DOM和业务请求。
- 服务：`src/modules/image/service.js`；修改前与同模块场景成员对齐。
- 场景定义：`src/modules/image/definition.js`；类型：同目录 `contracts.d.ts`。
- 公共映射见[统一设计](../define-shared-foundation/design.md)，代码分工见[开发索引](../../../docs/TEAM_DEVELOPMENT.md)。

### 模型与资产

采用 MIRROR，固定源码提交 `7f108fdd5c132e205df6f24954045cc9ba533361`。使用匹配的 DINOv3-H+ 底座、检测检查点和记忆模块；实际检查 Phase 2 是否已包含 Phase 1 参数，不重复覆盖，不用随机或裸骨干结果替代检测器。按上游预处理验证类别索引、裁剪和归一化，避免双重归一化。

资产放 `/home/lvjiawen/work/baselines/mirror/`（实际 `/data/lvjiawen/baselines/mirror/`）。已有 H+ pth 保持原样，检查 HF 目录兼容或正式转换路径，不能直接改后缀。下载固定版本并记录大小、哈希、来源和许可；网络镜像不绕过访问授权。

MIRROR 与 DocShield/OCR 使用隔离环境。默认物理 GPU 3，必要时按3→2→1→0选择，通常单卡；部署通过服务端配置指定 GPU 和模型路径，不默认使用全部显卡，不修改其他科研环境。

### 服务与数据

沿用 Node.js 场景入口，建议由独立 Python 常驻推理进程提供模型能力，目录和内部协议与组长对齐。公共上传、任务、版本、保存、权限和报告继续引用统一设计，不另建不兼容状态系统。请求中使用正式材料引用；结果携带实际材料版本、模型/预处理版本、类别及原始分数、覆盖范围和失败原因，字段名在公共契约中对齐。

批次按图片分别处理；坏图、超时或 OOM 不清空成功结果。模型不可用时明确失败或未执行，不自动切换未批准的外部服务。重试保留原任务和材料关系；修改材料后旧结果不充当新版。

### 页面与报告

沿用原生 JavaScript，接入 `pages/general.js`。展示上传、逐项进度、缩略图、原图与结果、来源倾向/分数及状态筛选；原图是本次上传材料，不声称获得未知的真实原作。报告基于服务端保存的实际结果，包含失败、限制与版本，不由前端合成真实性总分。

### 评测和顺序

先验证文件、模型加载和单例，再从 `/data/aigc/datasets` 的已有数据中核对授权、标签和真实负例，按来源/生成器分组测试误报与召回。性能和阈值在验证集确定，独立测试前固定；不直接引用论文指标作为本机成绩。参见[资产与验证](../../../docs/image-workstream/assets-and-validation.md)。

## Risks / Trade-offs

- 原生 pth 与上游 HF 加载方式不一致 → 验证参数完整性和输出，不覆盖原资产。
- MIRROR 许可及底座条款需分别核对 → 研究验证与正式交付分别记录可用范围。
- 文档页、截图和压缩输入可能域外 → 明示范围并分组评测，不推断登记真实性。
- 公共接口尚未落地 → 按统一标注样例开发，真实联调后才能交付；修改共享文件先对齐。

## Migration Plan

先形成模型与契约验证记录，再接服务和页面；新依赖、客户端打包清单与 OpenAPI 在对应实现 PR 更新。启用本场景时更新其空白/501测试，保留其他未实现场景行为。异常时禁用本场景服务并明确不可用，历史报告保留原模型版本。由维护者合并 main 后同步规格归档。
