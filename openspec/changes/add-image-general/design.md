### 模型与资产

采用 MIRROR，固定源码提交 `7f108fdd5c132e205df6f24954045cc9ba533361`。使用匹配的 DINOv3-H+ 底座、检测检查点和记忆模块；实际检查 Phase 2 是否已包含 Phase 1 参数，不重复覆盖，不用随机或裸骨干结果替代检测器。按上游预处理验证类别索引、裁剪和归一化，避免双重归一化。

资产放 `/home/lvjiawen/work/baselines/mirror/`（实际 `/data/lvjiawen/baselines/mirror/`）。已有 H+ pth 保持原样，检查 HF 目录兼容或正式转换路径，不能直接改后缀。下载固定版本并记录大小、哈希、来源和许可；网络镜像不绕过访问授权。

MIRROR 与 DocShield/OCR 使用隔离环境。默认物理 GPU 3，必要时按3→2→1→0选择，通常单卡；部署通过服务端配置指定 GPU 和模型路径，不默认使用全部显卡，不修改其他科研环境。

### 服务与数据

沿用 Node.js 场景入口，建议由独立 Python 常驻推理进程提供模型能力，目录和内部协议与组长对齐。公共上传、任务、版本、保存、权限和报告继续引用统一设计，不另建不兼容状态系统。请求中使用正式材料引用；结果携带实际材料版本、模型/预处理版本、类别及原始分数、覆盖范围和失败原因，字段名在公共契约中对齐。

批次按图片分别处理；坏图、超时或 OOM 不清空成功结果。模型不可用时明确失败或未执行，不自动切换未批准的外部服务。重试保留原任务和材料关系；修改材料后旧结果不充当新版。

### 页面与报告

沿用原生 JavaScript，接入 `pages/general.js`。展示上传、逐项进度、缩略图、原图与结果、来源倾向/分数及状态筛选；原图是本次上传材料，不声称获得未知的真实原作。报告基于服务端保存的实际结果，包含失败、限制与版本，不由前端合成真实性总分。

### 评测和顺序

先验证文件、模型加载和单例，再从 `/data/aigc/datasets` 的已有数据中核对授权、标签和真实负例，按来源/生成器分组测试误报与召回。性能和阈值在验证集确定，独立测试前固定；不直接引用论文指标作为本机成绩。参见[资产与验证](../../../docs/image-workstream/assets-and-validation.md)。

## Risks / Trade-offs

- 原生 pth 与上游 HF 加载方式不一致 → 验证参数完整性和输出，不覆盖原资产。
- MIRROR 许可及底座条款需分别核对 → 研究验证与正式交付分别记录可用范围。
- 文档页、截图和压缩输入可能域外 → 明示范围并分组评测，不推断登记真实性。
- 公共接口尚未落地 → 按统一标注样例开发，真实联调后才能交付；修改共享文件先对齐。

## Migration Plan

先形成模型与契约验证记录，再接服务和页面；新依赖、客户端打包清单与 OpenAPI 在对应实现 PR 更新。启用本场景时更新其空白/501测试，保留其他未实现场景行为。异常时禁用本场景服务并明确不可用，历史报告保留原模型版本。由维护者合并 main 后同步规格归档。


## 2026-10-29 整图检测解释可视化

研究 MIRROR 遮挡归因热图，标注其为模型响应变化而非像素级生成真值。ELA 仅为压缩误差分析，不作为 AI 结论。先验证预处理坐标映射、原始分数与遮挡分数、成本和稳定性，再接入用户界面。


## 通用图片前端增量

支持 JPG/PNG/WebP，每批8张、单张10MB、合计24MB，浏览器验证可解码且不超过4000万像素；支持拖拽、删除和清空。真实结果按图片ID绑定，失败不作为低风险。不接入模拟分数或热图，明确提示检测接口尚未开放。服务端协议待实现：POST action=detect，id绑定一次图片版本，file含name/mediaType/contentBase64；成功返回data.id/status=completed/verdict=likely_ai或no_obvious_ai，summary与coverage可选字符串。该协议为前端对接草案，不宣称后端已支持。


## 2026-10-31 可追溯诊断与商用结果展示

采用用户指定DDA H+发布模型，保留原336中心裁剪与FP32推理；新增真实HTTP检测、来源元数据、官方C2PA离线验证、压缩差异与高频残差诊断、双遮挡敏感性区域。热图记录原分数及遮挡分数，固定阈值0.05且两种遮挡均超过才标记，后台留存分类响应方法和实际中心检测范围；客户界面按2026-11-01精简方案展示。元数据缺失、C2PA不存在不计入AI风险。凭证的签名/内容绑定/信任状态分别保存，禁止远程凭证抓取。新增真实数据集示例与报告导出。


## 2026-11-01 客户展示精简

客户页面不展示中心裁剪范围及虚线框、遮挡次数、阈值和开发验证说明。通用图片高亮命名为“疑似AI成图区域”，不显示重复的分数释义和免责式文案；透明度只控制图层显示，有可见高亮时提供“高亮透明度”。后台检测、分数及留档保持原含义，不将分数改称真实性概率。


## 2026-11-01 完整实测示例与评测展示

示例必须含实际原图、DDA分类、SEED定位、本地内容核验及已实际调用的智能单文件/跨文件核验；缺失阶段补跑，按SHA256对齐，不补写模拟成功。原图默认可见，用户可切换两份材料。通用图片页默认展示具体实测图片，同时保留用户上传入口；不会在浏览页面时触发推理。页面下端按用户提供的八项Qwen-Image-Bench本地TPR降序展示DDA-H＋、PGC、PROBE、SAFE，突出DDA列但如实标记并列及SAFE更高项，不将TPR改称准确率。

### 2026-11-02 后续展示与流程修订

评测表仅展示生成模型、智鉴、方法1、方法2、方法3，删除本地实测标签、介绍句和排序说明，保留原始成绩及最高值样式。

### 2026-11-02 总项目集成交付

基于团队 main `949f08a`，保留其他场景与esbuild，接入图像异步路由和独立OpenAPI片段；材料页面适配共享API已解包业务对象的契约。静态服务限制为客户端资源，服务端源码不得外发。验证记录见 `docs/image-workstream/team-delivery-20261102.md`。

### 2026-11-02 固定图像检测示例与诊断呈现

将已有真实检出且包含6处遮挡响应的腕表生成图片制作成前端静态示例，独立放在上传工作台之后、Benchmark之前，按原图、疑似AI成图区域、检测及来源诊断三栏展示。用户清空或上传不影响示例，示例不依赖API或runtime文件。首页不展示真实样本和漏检样本，后台历史评测原始数据保留。元数据、凭证状态、诊断缩略图使用统一卡片样式；缺失元数据不推断为生成证据。移除评测区QWEN-IMAGE-BENCH标头。区域响应与整图检测共用一套结果。

检测结果与来源辅助诊断并排时使用网格等高拉伸，使两张卡片底部对齐；窄屏保持上下排列，不设置固定高度。


### 2026-11-02 批量上传与资源排队

图片与ZIP合计最多100张，每张10 MB，批次解压后总量500 MB，ZIP本身最多100 MB。浏览器流式解压并限制实际输出，忽略非图片及目录，不解压嵌套压缩包，不写入文件路径。逐张上传并轮询，服务端FIFO调度，仅单张占用GPU；无空闲GPU时每15秒重试，等待时间不计入推理超时。排队期间显示队列位置和等待提示。当前队列为单服务进程内队列，重启不恢复。


### 2026-11-02 结果浏览体验

结果区使用固定于滚动视口顶部的浏览工具条，显示文件名、当前序号/筛选后总数、上一张/下一张，下方提供当前项附近缩略图。首尾按钮禁用，支持结果区左右方向键，切换保持当前筛选及每图图层。后台推进任务不再强制选中正在处理图片。100张×单张10 MB统一为1000 MB批次限制；ZIP文件仍限制100 MB，展开总量1000 MB。

### 2026-11-03 共享GPU部署参数

目标端DDA完整推理在8 GiB PyTorch分配上限下成功，实测峰值预留3.65 GiB。将空闲显存门槛做成环境配置，默认仍为24000 MiB；正式服务器配置12288 MiB空闲门槛、8192 MiB PyTorch分配上限，给上下文及共享负载预留余量。DDA与SEED均遵守该分配上限，继续动态选单卡，不指定固定编号；无满足条件的卡仍按原逻辑排队。

### 2026-11-03 全图特征分布升级

新增独立的全图重叠窗口模型评分图，替代客户界面的中心遮挡方块默认图。整图分类score、阈值及Benchmark保持原部署口径；窗口得分不作为新的整图概率或像素真值。最长边1024的分析副本以336窗口、最多168步长覆盖全部像素，短边不足336时对称填充；批大小4。重叠窗口按中心平滑权重汇总，固定0至1色标，不对每张图拉满颜色。保留原中心遮挡响应在后台记录。界面名称统一为“AI 特征分布”，移除“几处AI区域”的计数，显示弱到强的色带。细节图配简短用途说明，移除无业务意义的均值数字；凭证状态与来源记录分别呈现，不因凭证缺失改变检测结论。静态示例从新的真实推理结果重新生成，保留来源哈希与窗口记录。覆盖正方形、横竖图及小图测试，验证边缘覆盖、坐标、固定色标、原分数不变以及页面交互。
