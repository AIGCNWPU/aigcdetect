# Design

## Context

当前采用原生JavaScript模块、CSS和Node.js HTTP服务，参考VERITAS项目前端设计；当前只展示4个模块与10个空白场景。`jumu-team/jumu`用作团队协作组织参考，未迁移其业务与Next.js依赖。

## 已接入框架的实际映射

| 公共入口 | 当前实现与边界 |
| --- | --- |
| `src/catalog.js` | 聚合四个模块定义，派生10个场景 |
| `src/modules/*/definition.js` | 各模块的场景、名称、路由和API元数据 |
| `src/modules/*/pages/*.js` | 10个独立空白场景渲染函数 |
| `src/modules/registry.js` | 聚合客户端场景注册，不含服务端实现 |
| `src/app.js` / `src/styles.css` | 公共顶栏、侧栏、模块卡片、面包屑和路由 |
| `src/api.js` / `src/contracts.d.ts` | 请求封装及场景级初始类型 |
| `src/modules/*/service.js` | 各模块业务接入点，目前均抛出未实现错误 |
| `src/server/registry.js` | 服务端模块分发；不进入浏览器打包 |
| `scripts/serve.mjs` | 静态预览、健康检查、目录及10个501业务接口 |
| `scripts/openapi.mjs` / `docs/openapi.json` | 运行时接口和交付快照，均由场景配置生成 |
| `scripts/source-files.mjs` / `scripts/build.mjs` | 无依赖离线构建，新增客户端文件须同步打包列表 |

## Decisions

- 页面注册与服务注册分别维护；业务算法、密钥和数据不得进入浏览器打包。
- 当前业务POST接口是场景入口占位，没有解析或验证业务请求体；接入真实业务时先约定请求schema、大小限制、鉴权与响应，不能把目前的空对象当作完成的API。
- 前端Hash路由与API路径分开。原始输入、文件和任务标识由正式公共后端定义，不在本次框架里伪造。
- 部分结果、覆盖不足和服务失败必须分开表示；只有模型实际处理后才展示对应风险线索。
- 论文/新闻/网文可分别开发；图片与视频售后场景将来通过同一案件标识关联材料，不复制或互相改写对方结果。
- 证件票据和报告需要按需求脱敏；密钥、访问控制、存储保留期限由公共能力实现时补充。

## 最少公共交付与供应顺序

两位组长共同负责以下公共能力，具体实现与入口在接入时更新，不预先指定数据库、队列、模型或供应商。

| 优先顺序 | 最小交付 | 各场景可并行推进的内容 |
| --- | --- | --- |
| 1 统一样例与引用 | 同一组文本、图片、视频、音频及售后案件样例；明确材料/文件及版本、任务、结果与问题位置的必要语义 | 按约定样例开发自己的页面与业务，样例明确标注 |
| 2 内容保存与版本 | 原材料与结果能保存、读取并保留历史关联；更新依据发生冲突时明确提示 | 各场景不另建互不兼容的版本系统 |
| 3 文件与预处理 | 统一上传、访问和下载入口，提供文档解析、媒体预处理支撑；支持范围由接入时验证 | 论文、证件和视频场景重点复用支撑，业务核对由各负责人完成 |
| 4 任务、配置与报告 | 记录任务、结果引用及失败原因；统一服务端配置与报告导出基础能力 | 业务负责人自行接入模型、维护报告内容并验证真实结果 |

登录与材料访问权限在部署共享环境前完成；本机样例开发不代表已有正式权限。公共服务尚未就绪时使用契约样例，联调交付前接回真实服务。不得在缺少结果时填造风险分数。

## 六人分工与最少交接

人员与场景归属以[开发索引](../../../docs/TEAM_DEVELOPMENT.md)为准，保留10个工作包。①只做论文，②负责新闻与网文；③负责通用图片和证件票据，④负责售后图视频，⑤负责通用视频和换脸，⑥负责音频。

- ①②统一文本结果与原文位置格式，具体场景各自完成，不要求②依赖论文处理流程。
- ③提供通用图片AI来源结果，⑤提供通用视频AI来源结果、范围、时间段和代表画面；④按原材料版本引用结果，完成自己的修改线索、商品核对及案件业务。售后视频不依赖人物换脸完成。
- ④的售后图片与视频共用案件引用，材料、结果、修改线索和核对问题分别保留来源。证件票据的篡改检查由③负责，双方按需复用算法，不互相调用对方的场景流程。
- 各类AI来源风险、篡改线索、校对问题、重复水稿、信息不一致分别表达。结果绑定原文、图像区域或音视频时间段及对应材料版本；版本修改后重新检测。
- 当前类型仍为场景级占位。上述是待落地语义，不宣称已存在文件、任务、版本或检测结果接口；详细字段随公共接入在同一PR更新契约和调用方。

## Owner Follow-up

按上表优先提供样例和内容读写，再补文件、预处理与任务等能力，并更新真实可用入口。六位同学可同步独立开发；具体技术选型和字段在实现时细化，不提前把占位写成生产能力。
