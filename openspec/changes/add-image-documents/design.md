# Design

## Context

范围见[proposal](proposal.md)，验收见[spec](specs/image-documents/spec.md)。当前已有独立场景页和真实异步材料核验接口；完整公共平台集成仍待完成。2026-10-26增量以文末方案及对应交付记录为准，早期分节保留历史上下文。

## Goals / Non-Goals

面向中文证件票据中的字段问题，直接展示疑似篡改区域与解释，结合本材料及同批跨材料规则核对。PDF与Word是同步输入适配，不新增场景。外部API按最新授权支持必要内容的脱敏/原文按需复核，默认脱敏；不重新训练、不承诺恢复篡改前未知字段，不将号码规则或材料一致性解释为登记真实性。

## Decisions

负责人：③ 吕佳文。负责2.3证件票据图片风险、篡改、字段及号码关联校验；复用自己维护的2.1来源检测。号码校验不等于身份真实，各类风险与字段问题分别展示，报告脱敏。

- 页面：`src/modules/image/pages/documents.js`，本轮实现批量上传、核心材料选择、解析状态与证据结果。
- 服务：`src/modules/image/service.js`；修改前与同模块场景成员对齐。
- 场景定义：`src/modules/image/definition.js`；类型：同目录 `contracts.d.ts`。
- 公共映射见[统一设计](../define-shared-foundation/design.md)，代码分工见[开发索引](../../../docs/TEAM_DEVELOPMENT.md)。

### DocShield历史对照与OCR补充

DocShield-9B直接接收材料图片，不依赖外部OCR作为输入。固定revision为 `be48c35e645e4c9382f33c67d492172823b2be8d`，模型卡声明支持中文、区域坐标、逐区域解释、逻辑异常和风险评分；发布脚本实际解码生成报告文本。因此增加输出解析与校验，保留原始报告，不将“结构化报告”当成已有严格JSON接口。

有效坐标映射到原图后直接绘制疑似篡改框，重点测金额、日期、号码及密集票据文字。模型指出的数值/日期矛盾进入规则核验；视觉线索和内容问题分开。其引用的文字和可解析字段均可保存，但全字段转写与逐字段置信输出不是已验证能力。生成风险评分不得代替识别分数或校准概率，没有相应分数时保留缺失。

PP-OCRv6 medium det/rec提供文字框、识别文本和识别分数，为全量字段核对、跨材料比对和脱敏提供补充；它不判定文字是否被篡改。DocShield作为历史对照独立运行；当前主链是MIRROR、SEED、OCR与本地规则。若部分材料能够直接满足字段完整率和精确率，可优化该路径，不预先承诺全部替代OCR。来源见[技术边界](../../../docs/image-workstream/architecture.md)。

### 字段与坐标证据

平台为DocShield、OCR、PDF文本层和人工输入分别记录实际材料版本、页/图、位置、原始文本、规范化值、模型版本和分数类型。原始文本是当前提交材料中的可见值，不是篡改前真实值。文字框可能对应整行或多个字段，字段边界需明确映射，不把整行框谎称为精确字符框。

保留图像EXIF方向、模型输入尺寸、缩放/裁剪变换以及模型坐标格式。使用已知位置样本验证映射，禁止猜测坐标系；定位不可靠时保留问题描述并标记不可定位。OCR框与DocShield异常框分别存储，重叠关联只辅助定位，不伪造更精确的模型输出。

字段更正与主体关系更正均生成版本记录，重跑受影响规则。O/0、I/1、金额小数点等歧义不静默修正以通过校验；多个识别来源冲突时保留双方值。脱敏定位也须处理模型/OCR漏检并支持人工补框。

### 知识库和同批规则

首期本地规则与字段/关系索引优先。知识库保存材料模板、字段别名、标准依据、历史码表、审核过的关系和生效时间；上传材料不自动成为可信事实。明确材料类型及规则适用性后，执行号码、日期、明示生日/性别、票种字段、价税、大小写金额及完整明细合计检查；数值使用十进制定点计算，票种、币种、含税口径和舍入容差明确配置。

围绕明确的核心材料建立字段与关系索引，辅助材料只参与目标相关的比较；相同姓名、金额或地址仅产生候选，不能直接合并主体。比较前确认主体、角色、交易与时间，必要时请求人工确认。号码一位差异不能被精确索引遗漏，也不能由相似度抹平。仅在有独立主体关联证据时报告号码冲突。

采用[跨材料规则矩阵](../../../docs/image-workstream/cross-material-rules.md)的C01–C15与G01–G08覆盖：员工与公司报销、分期开票付款、红字重开、历史变更、同名主体及重复材料。没有完整集合时不强求单张发票等于合同/证明总额；去重后汇总，保留正负号及关联依据。不同有效期的事实可共存，无法决定哪份正确时只报告矛盾。

每项结果关联规则版本、输入字段版本和证据位置。候选检查语义PASS/FAIL/WARN/NEI/NOT_APPLICABLE/ERROR与公共契约对齐；缺证、未执行和系统错误不改成通过或伪造。任意证明材料先支持已识别字段的通用核对，专有业务受理规则须有模板/知识库来源，未覆盖部分明示。

### PDF辅助适配

在同一材料上传入口同步接入图片、PDF和Word。候选使用pypdfium2逐页渲染与文本读取，扫描页通过OCR；多页与混装材料保留页码、材料片段及坐标变换。图片与PDF页共享检测、字段和报告服务，不单独建设应用。

文本层不等于可见内容，关键字段需与渲染结果核对。逐页记录损坏、加密、超限和失败，不能只处理前若干页却称整份完成。限制总页数/像素/处理资源，PDFium调用受控串行或独立进程。文档页生成倾向不等于PDF编辑历史，数字签名核验不在本次范围。

### 前端、报告与公共接口

沿用原生JavaScript与 `/api/v1/image/documents`。页面按同批材料组织，分别展示来源风险、疑似篡改、字段核对和跨材料冲突。异常框默认使用SEED映射坐标，DocShield为可选对照，规则问题使用对应字段来源框，交叉冲突并排定位双方材料。用户可修改识别值和关联，但保留原始结论及修订历史。

报告列出范围、问题、证据位置、缺证/未执行项、模型/规则版本和人工复核记录。像素遮盖后生成独立脱敏输出；PDF适配时由脱敏页图生成报告，不复制原文隐藏层、附件或敏感元数据，并检查导出后文本与像素。鉴权、存储保留期、上传/下载、任务和版本系统按公共底座接入，场景不重复建设。

## Risks / Trade-offs

- 9B公开检查点与论文7B实验不同 → 按当前权重独立评测中文票据，不承诺论文成绩。
- 模型框和生成报告可能缺失、截断或无效 → 保留原输出、标注覆盖和解析失败，不补造框与字段。
- 逻辑异常可能被模型描述为伪造 → 规则独立核验，两类结论并存，验证“改过但正确/没改但有错”。
- OCR识别错可放大成核验错误 → 对照抽取、歧义复核及字段版本重算。
- 开放式证明模板尚不齐全 → 已有规则照常工作，未知业务条件列为缺证或未覆盖。
- 规则时效、模型/数据许可和公共接口未完全验证 → 记录适用范围，逐项完成验证后交付。

## Migration Plan

全部环境、缓存和输出放在 AIGC_PLATFORM_ROOT 下；运行前检查当前空闲GPU，默认单卡。同步接入场景服务、解析和页面。共享字段/服务/构建修改与组长及④对齐，在实现PR同步调用方、OpenAPI和测试。模型失败不回退到未授权API，禁用模块时保留真实不可用状态及历史报告。实施与验证完成并合并main后再归档。

## 2026-10-21 后端增量

场景内新增 `documents/server/batch-engine.js` 与有来源的金融材料目录，先验证字段证据、版本与可信关联，再执行基础金额/同批比较。目录覆盖建议不等于机构政策通过；业务专用规则设计和例外见[金融场景](../../../docs/image-workstream/financial-material-rules.md)。

`documents/python/pdf_adapter.py`、`pdf_evidence.py` 与本地验证入口已实现 PDF 分页、有限资源渲染、可选文本层提取和真实 OCR 来源回链。文本层尚未与可见图像完成一致性判定；脱敏、公共 HTTP/队列和前端待接入。详细能力与限制见[后端 PDF](../../../docs/image-workstream/backend-pdf.md)。规模测试严格分开真实性分类、文字提取、工程用例，不混为一项准确率。

## SEED 主测链路（用户更新）

使用固定源码和完整公开权重运行 SEED DINOv3 ViT-L/16 + LoRA + EoMT，输出像素 mask、连通区域和图像检测分数。原尺寸分块与补白变换明确记录，独立保存 mask 与 OCR 框，不把框重叠当修改证明。DocShield-9B 不删除、保留同样本比较。

DeepSeek 仅收到数值型相对区域、未校准检测分数、OCR 质量统计和枚举化规则结果；不发送图片、OCR 原文、姓名、证号、账户、金额、文件路径或材料哈希。提示词在本地独立文件可修改；API不能声称观察到未提供的视觉细节。原文与区域关联只留在本地。

密钥存被 Git 忽略的 `.env.image-documents.local`，权限 0600，不进入浏览器/报告/日志。仅官方 HTTPS 域名，拒绝重定向，禁用环境代理，限定超时/输出长度与单次选样数；失败/截断/无效证据引用均不能显示成功解释。全部报告明确标注生成解释不构成新增鉴伪证据。

这是隐私约束下的项目适配，不是原论文多模态 API 看图流程的完整复现。真实能力以同清单实测为准，不根据模型规模或论文成绩直接替换已验证结论。

## 2026-10-22 目标驱动审核设计

用户确认的新方案优先于前述历史记录。流水线为输入解析 → 每页MIRROR → 每页SEED → OCR/结构字段 → 每文件本地规则 → 核心文件驱动的跨文件规则 → 按条件生成脱敏解释。任一模型失败不阻断独立规则，阶段分别返回 completed/failed/not_run/partial；模型分数不称为概率或真实性结论。

审核请求包含 objective、coreMaterialId、materials、经确认的relations，不收集或依赖用户机构身份选择。第一版每批一个核心文件，多核心拆成独立审核目标；不枚举全部二元/三元组合。先按来源哈希去重，建立材料ID、字段、交易关联索引；只选择核心相邻的受信关系，明确声明完整的付款/票据集合按组聚合。索引构建与星状候选数量应随材料数线性增长，另限每批文件、页数、字段与边数；无关联辅助材料标记未参与和原因。相同姓名/金额不能成为可信关联。旧全对比较函数保留回归参考，目标流程不调用其全批枚举。

正则只用于字段形态与别名；十进制计算、日期时序、主体角色及集合关系独立执行，所有规则保留出处/版本/适用范围和证据位置。中文VAT票、收据、采购合同、付款凭据、科研审批与证明使用不同规则包。机构政策未知时返回NEI，不推导违法或法定有效性。

DeepSeek提示词优先参考经审核的开源对账/审计skills；它们是方法材料，不能取代本地计算或作为中国法律依据。外发仅枚举规则结论、相对位置与匿名证据ID。SEED触发可申请解释，未触发时仍完成所有规则且无自动API调用。每个调试批次明确预算（默认0，显式开启最多3次），缓存按脱敏摘要与提示词版本绑定，限制超时和token、不自动无限重试；本轮测试默认使用离线替身，真实调用仅明确启用调试时执行。输出必须引用已提供证据，不能新增事实，不能声称看图；定位合理性仅评价本地位置/字段/规则的支持程度。

解析接收真实图片、PDF和DOCX，限制解压大小、页数、像素与执行时间；不执行宏、不访问外部文档关系。DOCX以段落/表格位置为来源，需本地转换器渲染后才能进行视觉分析；缺少转换器或旧DOC不能处理时显式列为未完成，不能冒称已检测。页面的核心/辅助角色、解析覆盖、四类风险和未执行状态同步展示。

首版HTTP为场景范围的本地开发集成，沿用既有端点与响应信封；公共登录/权限/长期存储未就绪时不声称生产部署完成。其他9个场景保持现状。共享HTTP与打包仅做本场景必要接缝，契约和变更在文档列明供组长接入。

## 2026-10-23 功能入口修正

前台、场景目录及OpenAPI移除用户角色清单和身份字段，不按机构类别限制功能。目录只按核验目标及材料适用类型分派；购方/销方/付款方等材料中的语义角色继续保留，不能与登录用户身份混淆。历史请求携带的role字段不参与判断且不回显到计划。新测试覆盖无需身份即可选择全部五个功能、目录无角色字段及选项无括号备注。

## 2026-10-26 实施设计（替代历史摘要专用与SEED触发约束）

1. 调研输出独立文档与版本化场景/政策目录。至少区分北京、上海、西藏材料研究；覆盖不足逐项列出。地区与机构只定义材料/规则适用范围，不形成身份菜单。制度来源记录URL、标题、公布/生效信息、查阅日期及适用限制。论文方法仅支持评价设计，不作为税务依据。
2. 本地评价采用门槛和四级执行度：A确定性已核验、B需语义复核、C证据不足、D规则/政策未覆盖。规则结论PASS/FAIL独立于等级。OCR分数仅为工程门槛，不能称准确率；保留各维度、原因和覆盖分母。低质量OCR先补证/重读；证据充分的未覆盖语义进入模型，不把所有NEI都发送。
3. 新增显示税率核验时必须有同一明确行或范围的净额、税额、数值税率、币种及可信来源。明确0%对应非零税额可判冲突；免税、不征税、星号、差额计税、混合税率/汇总未知范围不套此规则；不推断税率是否合法或抵扣资格。
4. 新的semantic-review模块接受本地批次/原文块/规则/计划，产生有上限的事项与证据包。单文件与核心邻接关系共用schema，保留证据ID和来源；无关材料不外发。包括待审背景、问题、相关原文、提取字段、关系确认、政策引用及输出约定。原材料中的指令一律作为数据。
5. privacyMode为redacted/original，默认redacted，另有semanticReview布尔开关。redacted以本次任务稳定代号替换主体、号码、账户等核心标识，不把原始文件名/路径/哈希送出；保存转换覆盖与信息损失，无法安全组织的片段拒绝发送或只保留字段摘要。original允许必要原文/字段，仍不发送整文件。切换模式使结果缓存失效。局部图片仅在已实现并验证裁剪与多模态端点后启用，本轮文字模式明确未发送图片。
6. 模型返回schema包含总体reasonable/issues_found/needs_more_information，summary、逐事项结论/解释/证据ID/建议、警告；每个请求事项必须有结果，不准未知/跨事项证据、无解释、截断或未完成输出成为成功。本地确定FAIL不被模型合理结论覆盖。政策只能引用已提供且适用的来源；过期/未核实不造新政策。
7. 生产接缝使用服务器配置，客户端不能提供端点、密钥、system prompt或任意URL。配置关闭/预算耗尽/失败明确not_run/failed；持久任务预算最多1次请求，失败不自动重试，缓存绑定模型、提示词、证据、模式与版本。不通过测试读取密钥；使用可注入替身与少量明确选定的真实样本验证。
8. 最终结果聚合为用户结论、警告、待补项、完成范围、AI复核摘要与材料定位。前端默认不展示模型名、分数、内部规则码或工程限制大段文字；保留可展开的依据和简短平台声明。等待提示原样显示。语义未执行时不得显示智能复核通过。
9. 评测包括地域适用与错用、零税率及例外、来源/低质量证据、核心关系、脱敏泄漏/原文模式、预算缓存、伪响应和页面交互；新增实验使用新目录，原历史结果不覆盖。
