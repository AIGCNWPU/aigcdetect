# Spec Delta

## Purpose

简化 2.1/2.3 前端展示（智能复核为核心展示、收起明细、收敛选项、新增小票核验、示例位置调整），新增常驻推理服务消除冷启动等待，并提供 MCP 接入。

## ADDED Requirements

### Requirement: 常驻推理服务
系统 SHALL 提供常驻推理服务：启动时加载整图检测与篡改定位模型并持续提供本机 HTTP 推理接口；2.1 与 2.3 的对应阶段 SHALL 优先调用该服务，服务不可用时自动回退到按任务启动模式，两种路径的输出结构保持一致。

#### Scenario: 常驻服务可用时消除冷启动
- **WHEN** 常驻推理服务已加载模型且用户提交 2.1 或 2.3 检测
- **THEN** 对应阶段直接调用常驻服务完成推理，不再重复加载模型

#### Scenario: 常驻服务不可用时回退
- **WHEN** 常驻推理服务未启动或不可达
- **THEN** 对应阶段回退到按任务启动模式并正常完成，结果结构不变

### Requirement: 结果展示以智能复核为核心
2.3 结果页 SHALL 将智能复核结论置于结果区顶部并放大展示（含矛盾摘要），单份与跨材料明细、字段明细 SHALL 默认折叠；通过项 SHALL 以统计方式呈现而非逐条展开；同一事实不得在多个区块重复完整陈述。

#### Scenario: 打开核验结果
- **WHEN** 用户查看一次核验结果
- **THEN** 首屏呈现总结论与智能复核要点，明细需展开才见全文

### Requirement: 核验功能收敛与小票预选项
2.3 核验功能 SHALL 提供发票核验、证件核验、票据核验、其他核验四个选项，材料类型 SHALL 默认“智能选择”并在服务端自动识别；示例区块 SHALL 紧邻结果能力对比（Benchmark）区块之前展示。

#### Scenario: 小票核验
- **WHEN** 用户选择票据核验并提交小票照片
- **THEN** 系统按收据口径完成单份内容核验，无需用户再逐份选择材料类型

## ADDED Requirements

### Requirement: MCP 工具接入
系统 SHALL 提供 MCP server，以工具形式暴露通用图片检测、材料核验与字段提取能力，工具描述 SHALL 说明适用场景与能力边界，工具输出 SHALL 以结论摘要置顶、结构化数据附后。

#### Scenario: MCP 客户端调用检测
- **WHEN** MCP 客户端调用通用图片检测工具并提交图片
- **THEN** 返回包含结论摘要与结构化结果的工具响应，格式与市场 API 语义一致

### Requirement: 材料管理与图层状态保持
系统 SHALL 提供逐文件删除和全部清空，刷新核验进度及切换结果时保留每份材料的修改/模糊图层开关状态；清空后不得提交旧材料。智能核查证据桌面每行三项，小屏自适应布局。

#### Scenario: 检测期间关闭模糊标记
- **WHEN** 用户取消模糊标记后进度轮询刷新结果
- **THEN** 模糊标记保持关闭，修改标记的状态不受影响，切换文件后再回来仍保留该选择

#### Scenario: 清空后上传新材料
- **WHEN** 用户清空材料并重新上传
- **THEN** 新请求只包含新文件，旧结果和关联确认均清除

### Requirement: 干净检出的可重复构建
平台 SHALL 从锁定的 npm 依赖自动准备浏览器需要的资源，源码预览和生产构建不得依赖未提交的人工复制文件。

#### Scenario: 新机器检出工作分支
- **WHEN** 开发者或 CI 在干净目录执行 npm ci 及 npm run build
- **THEN** 浏览器压缩包依赖与许可自动准备，构建成功，源码和构建页面的对应资源均可访问
