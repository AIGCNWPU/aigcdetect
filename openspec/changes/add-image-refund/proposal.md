# Proposal

需求章节：2.2 仅退款与售后AI凭证检测（需求摘录第7页）。负责人：④ 闭耀松。状态：规格待评审，业务待实现。

## Why

客服需要按售后案件核查破损照、污损照等图片，区分整图AI生成、局部修改和商品描述不一致，并能找到对应凭证进行补证或申诉复查。当前只有独立场景入口和501空接口，已有规格尚缺可直接验证的行为及服务交接条件。

## What Changes

### 本轮提交范围

- 沿用本工作包，细化 proposal、spec、design、tasks 四份文档，提交规格评审PR。
- 补齐正常处理、无效输入、局部失败、覆盖不足、补证及版本变化的验收场景。
- 明确公共底座、③通用图片检测和3.3售后视频的交接范围；列出实际开发前必须完成的对齐事项。
- 本轮不改页面、服务、公共协议及其他工作包；不勾选业务任务、不同步正式规格、不归档。规格评审通过不代表业务已实现。

### 工作包的业务范围

1. 按售后案件整理图片凭证，关联商品资料及用户问题描述。
2. 引用③的通用图片AI来源结果，逐图展示实际材料版本对应的生成风险及检测范围。
3. 检查破损、污渍等区域的添加、替换、拼接或消除线索，在原图上定位，并与整图来源风险分别展示。
4. 核对商品外观、款式及可见问题与资料、描述的一致性；资料缺失或画面不足时明确待补充内容。
5. 按案件汇总每张图片的三类结果与待核对问题，保留补证及历史结果关联，为3.3提供同案图片结果引用。

### 非目标

自动批准或拒绝退款、自动认定欺诈；自建通用图片来源检测；2.3证件票据及3.3视频处理；另建公共案件、身份权限、文件、任务或版本系统；本轮选择并接入模型供应商、生产部署。2.2本轮不新增独立报告导出需求，后续如需导出复用公共能力并另行确认范围。

需求来源见[需求摘录](../../references/AI检测平台_需求摘录.md)第7页；跨场景归属见[开发索引](../../../docs/TEAM_DEVELOPMENT.md)。

## Capabilities

### New Capabilities

- `image-refund`：售后图片整理、AI生成风险、局部篡改定位、商品描述核对及案件风险汇总。沿用已有增量规格，尚未同步为正式能力。

### Modified Capabilities

无。

## Impact

本轮仅修改本目录四份文档，无运行时接口变化。场景 `#/image/refund` 与 `POST /api/v1/image/refund` 保持现有占位状态，所有10个业务接口仍为501。

后续实现入口、必要输入输出和依赖见[设计](design.md)。公共字段、状态和跨场景引用遵守[公共约定](../define-shared-foundation/specs/shared-foundation/spec.md)，不在本工作包重复定义。涉及公共服务与图片模块共享文件的修改，实施前与组长、③对齐；同案图视频使用统一案件引用，3.3仍单独维护。
