# Design

## Context

范围见[proposal](proposal.md)，行为验收见[spec](specs/image-refund/spec.md)。本轮仅提交规格细化；下述方案均为拟实现内容。

当前 `src/modules/image/pages/refund.js` 不创建DOM或请求；`src/modules/image/service.js` 的所有场景均抛出未实现错误；`contracts.d.ts` 仅有请求占位类型。HTTP层 `scripts/serve.mjs` 尚未读取业务请求体，文件、案件保存、任务、权限和检测服务尚无真实接口。现有检查与测试只证明空框架行为。

公共框架映射以[统一设计](../define-shared-foundation/design.md)为唯一来源；公共业务行为引用[公共约定](../define-shared-foundation/specs/shared-foundation/spec.md)，职责遵循[开发索引](../../../docs/TEAM_DEVELOPMENT.md)。

## Goals / Non-Goals

**Goals:** 在现有图片场景内完成“案件材料→三类独立检查→定位复核→案件汇总”的实现设计；让每项结果可追溯到实际材料和核对依据，为3.3复用同案图片结果提供边界。

**Non-Goals:** 本轮不实现业务或确定公共字段、状态枚举与模型供应商；不重建公共服务，不改变其他场景接口。完整业务与非目标见proposal。

## Decisions

### 1. 在既有工作包内细化，分阶段接入

负责人为④闭耀松。沿用原生JavaScript页面和服务端模块入口，先对齐公共样例和必要语义，再接真实服务。与自行建立独立案件后端相比，这样可避免2.2与3.3产生不兼容的材料、版本和权限体系。样例仅用于明确标注的开发与契约验证，不能替代真实业务验收。

### 2. 页面按案件组织，三类结果分开查看

- 案件资料区：展示当前案件、商品资料与问题描述，可进入补充或修订操作；进入哪个案件、如何保存由公共能力对接，不另发明公共路由。
- 凭证列表区：添加一张或多张图片，逐张显示预览及处理状态；无效文件说明具体原因，可用文件继续处理。
- 图片复核区：保留原图预览，将AI来源、局部修改和商品描述核对分开显示。局部区域标注可切换以对照原图；核对问题展示资料依据和画面依据。
- 案件汇总区：逐图汇总三类结果、缺项及待补证内容，点击问题回到对应图片。历史结果注明实际材料和依据版本。

选择同页复核而非每个检查独立跳页，是为减少客服在原图和结果之间切换。仅定位和提示人工核查，不增加退款审批按钮或无依据的综合分数。

### 3. 必要输入输出采用公共引用，具体字段待对齐

下表约定业务语义，不是已发布的JSON契约。公共标识、版本、状态、错误及权限语义只引用公共规格；实际字段名及编码需在对齐后写入共享契约与OpenAPI。

| 环节 | 必要输入 | 必要输出与校验 |
| --- | --- | --- |
| 凭证整理 | 有权限的案件上下文、图片文件/材料引用、商品资料、问题描述 | 逐图可读性及上传结果，关联实际案件和版本；无可用图片不启动检测 |
| AI来源 | 实际图片和版本，③提供的检测能力 | 有效来源风险、范围、证据来源；核对材料和版本，拒绝将错配结果挂到当前图片 |
| 局部修改 | 实际图片及其可用预处理信息 | 可疑区域、可验证的修改线索与依据、覆盖范围；缺失/越界位置不能作为有效定位 |
| 商品核对 | 图片、商品资料、问题描述及各自实际版本或不可变快照引用 | 按外观、款式、可见问题展示依据与待核对项；资料不足时输出缺项，不猜测 |
| 汇总与历史 | 同一案件内有效结果及公共处理状态 | 按图片分列三类结果和未处理项；供3.3按同一案件引用读取，不复制或改写视频结果 |

商品资料与问题描述可先不足，界面指出补充项；图片来源或修改检测不应被资料核对缺项错误地合并为失败。具体长度、文件类型、尺寸、数量和大小限制依公共上传与模型实测能力在接入前确定，前后端使用同一限制并验证边界。

### 4. 三类检查独立接入，结果先验证再展示

AI来源结果由③提供，本场景不重做通用图片检测，也不调用2.3证件流程。局部修改和商品描述核对由④负责选择适用的服务或模型；可以按需复用算法，但必须保留独立结果和覆盖范围。仅用通用大模型文字描述不能视为已经实现可靠的局部篡改定位。

服务端负责检查权限、材料/版本匹配、结果结构和区域合法性；客户端只展示获准返回的内容。局部位置需要与预处理后的方向、尺寸和原图建立明确映射；缩放预览只改变显示坐标，不改变证据位置。坐标格式与原图映射随公共预处理协议对齐，本轮不另定公共格式。

相比把三类检查合成一个总分，独立接入允许保留已完成项，并准确说明某项不可用或部分覆盖。对无结果、失败、未覆盖和实际未发现问题的表达完全遵循公共约定。

### 5. 补证与修订保留实际依据

新增图片没有继承结果；替换图片创建新的材料版本并提示重新检测。商品资料或描述更新使旧核对结果成为历史依据下的结果，需提示重新核对。未变更图片的来源与局部检查结果仍可按原版本查看；是否能在新任务复用由公共任务/版本规则决定，本工作包不定义缓存策略。

异步结果即使晚于修订返回，也只能关联其原任务与原输入版本；当前案件视图不得把它当作新输入结果。失败后的重试保留历史引用，遵循公共任务规则，不覆盖旧证据。

### 6. 待框架对接的目录、接口和服务

| 入口 | 后续拟变更 | 边界 |
| --- | --- | --- |
| `src/modules/image/pages/refund.js` | 案件输入、逐图预览、三类结果与区域定位、汇总和补证交互 | ④场景页面；不放模型密钥 |
| `src/modules/image/service.js` | 在refund分支接入校验、服务编排和结果整理 | 与③对齐，其他图片场景保持原行为；必要时拆场景服务 |
| `src/modules/image/contracts.d.ts` / `definition.js` | 补充已对齐的场景请求响应和真实接入状态 | 不提前将implemented标为true，不复制公共类型 |
| `POST /api/v1/image/refund` | 接收已对齐的案件、材料及核对依据引用，返回真实任务/结果 | 当前仍是501占位；同步或异步返回形式须先与公共任务接口对齐 |
| 公共文件、版本、权限、任务及保存服务 | 引用统一上传、读取、版本和鉴权能力 | 入口尚未交付，由组长维护，不能以浏览器本地存储冒充正式能力 |
| `scripts/serve.mjs` / `scripts/openapi.mjs` / `docs/openapi.json` | 对齐后接入请求读取、限制、权限及契约描述 | 公共文件由组长统筹，本轮不改 |
| `scripts/source-files.mjs`、公共样式与回归测试 | 新增客户端文件时同步构建清单，限定场景样式，更新已实现场景的占位断言 | 提前与组长对齐；服务端与密钥不进入客户端包 |

## Implementation Prerequisites

以下事项阻塞真实业务接入，本轮PR供范围和对接评审，不代表这些事项已完成：

| 对齐对象 | 实施前需确认的交付 | 验证证据 |
| --- | --- | --- |
| 组长/公共底座 | 案件、图片和商品资料/描述的保存及版本引用，权限校验，文件限制、预处理坐标映射，任务状态与错误协议 | 可调用接口及一致的正常、无权限、修订、失败样例；契约及调用方一起更新 |
| ③通用图片负责人 | AI来源结果入口、材料版本与覆盖范围，失败及版本错配响应 | 对同一图片版本的可调用结果；不得仅提供没有来源的风险数值 |
| ④场景负责人 | 局部修改定位与商品核对的服务方案、真实样本、覆盖范围和验收标准 | 覆盖添加/替换/拼接/消除及未修改对照的评估记录；清楚标出不支持项，重大范围不足先调整方案或重新确认规格 |
| ④的3.3工作包与组长 | 同案图片结果读取与权限边界 | 相同案件引用、不同案件隔离及旧版本结果的契约样例；视频实现仍在独立工作包 |

算法效果阈值、供应商和支持的文件范围没有现成约定，不能从本轮文档推断已选定或已验证。前期允许依统一样例推进页面；真实服务选型和对齐结果需回填本设计后才能宣称功能交付。

## Risks / Trade-offs

- 通用AI来源风险不能证明局部篡改 → 分别显示，两者冲突时保留各自依据供人工复核。
- 模糊、压缩或遮挡会影响检测与核对 → 显示实际覆盖和资料缺项，以补证处理，不推断低风险。
- 图片旋转、缩放或预处理导致标注偏移 → 保留原图映射，用不同方向和尺寸样例验证，拒绝无效区域。
- 公共接口尚未交付 → 用明确标注的统一样例验证交互和契约；真实联调作为业务交付前置条件。
- 模型能力不足或误报 → 用真实对照样本记录结果与局限，未达到已确认范围时不勾选完成；本轮不承诺未实测的准确率。

## Migration Plan

本轮只有文档变更，无数据迁移或部署。规格评审后，按tasks完成前置对齐并在个人分支小步实现、自检、提交代码与规格PR，由组长合并。实现并验证后才同步正式规格与归档；当前文档提交不能触发归档。
