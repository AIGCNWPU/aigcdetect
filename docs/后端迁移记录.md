## HTTP 服务

`server.py`（FastAPI + uvicorn）把 `engine.py` 包成接口，`detect.py` 与它共用同一个引擎，避免逻辑分叉。

```bash
cd /mnt/vos-6d37s2q0/users/zqy/projects/audio-antispoof
./run_server.sh start     # CUDA_VISIBLE_DEVICES 可指定卡，PORT 可指定端口
./run_server.sh status
./run_server.sh stop
```

| 接口 | 说明 |
| --- | --- |
| `GET /api/v1/health` | 返回 `modelLoaded` / `device` / `loadSeconds` |
| `POST /api/v1/audio/forgery` | `{"sampleId":"wav1"}` 或 `{"audioBase64":"…","fileName":"a.wav"}` |

响应走 `{"data":{…},"requestId":"…"}` 信封，错误为 `{"error":{"code","message"},"requestId"}`：
`400 BAD_REQUEST` / `404 SAMPLE_NOT_FOUND` / `413 AUDIO_TOO_LARGE`（>25 MB）/ `422 AUDIO_UNREADABLE`。

超过 30 秒的音频自动按 10 秒窗、5 秒步长切窗，返回最可疑的一段并给出逐窗分数。

### 长音频实测

| 输入 | pFake | 窗口数 | 耗时 | 区间 |
| --- | --- | --- | --- | --- |
| 20 s 真人 | 0.0009 | — | 3.5 s | 无 |
| 20 s 伪造 | 0.9995 | — | 3.4 s | all |
| 60 s 真人 | 0.0293 | 11 | 23.2 s | 无 |
| 60 s 伪造 | 1.0000 | 11 | 38.5 s | all |
| 60 s 混合（20 真 + 20 假 + 20 真） | 1.0000 | 11 | 30.7 s | `[[15, 45]]` |

混合样本的逐窗分数是 `[0.001, 0.003, 0.029, 0.984, 0.997, 1.0, 0.999, 0.999, 0.001, 0.003, 0.029]`，真伪分离非常干净。

关闭切窗（整段 60 秒一次推理）也判得对（0.9627），但**失去定位**、且分数比切窗低，所以默认保留切窗。

两个在实测中修掉的 bug：

1. **假定位**：原先区间取"最高分窗口"，但 argmax 总会选一个，导致纯真人 60 秒音频也会报出 `[[10, 20]]`。改为"合并所有超过 0.5 的窗口"，无窗口超阈值则返回 `null`。
2. **覆盖率错误**：原先 `coverage.analyzed = min(duration, chunk_sec)`，60 秒音频永远显示"分析了 30 秒"。改为取最后一个窗口的结束时间。

代价是延迟：60 秒音频约 23–38 秒（每窗一次 7B 推理）。真实业务应改为异步任务 + 队列，而不是同步等。

**当前采用同步 + 硬上限**（演示阶段）：文件 ≤80 MB、时长 ≤120 秒，超限在探测阶段直接返回 `413`，不跑推理。两处守卫：

- 前端：拿到 `loadedmetadata` 后先判时长，超限不上传；
- 服务端：`engine.infer_media` 探测时长，超过 `MAX_MEDIA_SECONDS` 抛 `MediaTooLong` → `413 MEDIA_TOO_LONG`。

实测 152 秒文件：服务端 **0.05 秒**拒绝；经隧道的完整往返 **2.17 秒**（含 6.5 MB 上传）。`/api/v1/health` 会返回生效的 `maxMediaSeconds` / `maxUploadMB`。

异步方案留待接入真实长视频时再做。

### 视频输入

视频不能直接喂给音频模型，需要先抽出音轨。实现放在服务端（`engine.extract_audio`），因为浏览器没有可靠的容器解封装能力：

```
容器解复用 → 取第一条音轨 → 解码帧 → 重采样 16 kHz 单声道 → PCM16 WAV → 同一套推理
```

用 PyAV（自带 FFmpeg 7，**不需要安装 ffmpeg 命令行**）。支持的容器：`mp4 / mov / mkv / webm / avi / m4v / flv / ts`。

响应里会多出 `media: "video"`、`audioExtracted: true`、`audioDurationSec`（音轨时长）、`containerDurationSec`（容器时长）。视频没有音轨时返回 `422 MEDIA_UNREADABLE`。

前端对视频文件显示 `<video>` 预览（波形画不出来，浏览器无法解码视频容器里的音频），并跳过客户端波形绘制。

### 前端对接

页面加 `?api=` 即切到真实推理：

```
http://127.0.0.1:4173/?api=http://127.0.0.1:8000#/audio/forgery
```

不带参数时仍是离线样例模式。**云服务器 8000 端口未对外开放**，需要先开隧道：

```bash
ssh -N -p 22022 -L 8000:127.0.0.1:8000 zqy@101.200.176.142
```

已把本机公钥写入服务器 `~/.ssh/authorized_keys`，现在免密登录。

**踩坑记录**：一开始用 paramiko 自己写端口转发，小于 2 MB 的请求正常，6.5 MB 的 POST 会被重置连接（`WinError 10054`）。换成 OpenSSH 原生 `-L` 后正常。大文件转发不要自己造轮子。
