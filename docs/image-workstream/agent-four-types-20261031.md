# 四类非发票材料 Agent 实测（2026-10-31）

## 测试范围与方法

在独立协作仓库 develop 当前工作区使用师兄合入的 Claude Agent SDK 0.3.314 流程，实际调用 DeepSeek `deepseek-flash`，统一使用 `material-review` 运行时指引。没有使用模拟返回，也没有回退到 direct API。延续当前工作区的全材料内容核对逻辑，不是单独运行师兄提交的纯净历史版本。

选择本机 CrossCred 的四类现有材料：组08生活缴费凭证2份、组11授权书3份、组16销售合同2份、组18无欠税证明4份，共11份。每组第一份作为核心材料，生成单文件内容审核和核心对辅助文件的审核事项。不是合同、付款、发票混合业务链验证。

复用此前真实 OCR，每份原图与 OCR 记录的 SHA256 一致才执行；本轮重新运行字段提取、本地规则、执行分级、语义证据封装及 Agent。未重跑 OCR、MIRROR、SEED，也未向模型上传图片。按已有原文审核模式发送文本，作者标签仅在模型返回后另存用于对照。此数据集经过修改和脱敏，不能称为未经加工的真实商业凭证。

预算：4个会话，每组一次；每会话最多8轮、40次工具调用、180秒，无自动重试。使用项目原有四个取证/提交工具。API凭据仅由服务配置装入进程，未复制或打印。

## 检出与问题

| 类别 | 观察到的结果 | 尚有问题 |
| --- | --- | --- |
| 生活缴费凭证 | 识别同流水号、同户号但地址、收费单位、付款账号不同，返回明确警告 | 单文件因付款时间缺失等判信息不足；把 unsupported_field 错解为未识别；跨文件事项重复 |
| 授权书 | 指出同一授权经销合同号下张*松、刘*宇、王*浩不同 | 差异检出不等于证明授权冲突；模型额外推断重复/超范围授权。原文已有“大陆地区”，却称未载明区域；采购目标带来不相关的交付/结算补证要求 |
| 销售合同 | 识别周*晨与刘*长、收货地址差异；指出小写金额与大写贰佰元整不一致 | 第二份正文因全包文字块上限截断，签署区未完整送入；authorized_agent等结构化字段不在发送白名单。人员差异从收货文本发现，不能声称签署区委托代理人均核验。模型额外报告的甲方“市”字差异可能来自OCR，未作为确认的原图错误计分 |
| 无欠税证明 | 三对核心—辅助材料均发现同证明号下名称、税号不同，保留本地身份证号异常 | 将封装未支持字段臆测为机关/签章/日期缺失；对18位税号前缀的额外判断缺少明确适用依据，不能计作已验证错误 |

### 原图和标签的核对

组08作者描述户号36901233076，但原图与OCR显示36912303076；组18作者描述证明尾号3321，实际抽查原图显示8800909。因此按“同号材料中的内容差异”核对类别，不照抄作者编号，也不把作者标签当完全可靠的真值。

组16两图的小写金额不同，OCR分别为9998.0和9980；两图大写位置显示贰佰元整。原图金额较模糊的一份仍应复核，不能用OCR高分直接保证每个字符准确。组11差异确实存在，但材料没有“仅允许一个被授权人”的充分依据；模型把差异强化为确定冲突，是本轮明确暴露的问题。

### 输入封装问题

unsupported_field表示本地已抽取的字段键不在语义包支持列表，不表示OCR未识别。部分相同内容仍能通过文字块送入，例如户号和授权合同编号；模型不应把这类封装损失一律当作材料缺失。

文字块全包上限为100，按材料顺序占用。组16第一份占用较多，第二份后部被裁掉；需要按材料和审核事项均衡分配证据。当前测试不修改输入限制后重试，以保留原始基线。

授权组两对材料各生成“核心语义比较”和“候选关系上下文”两份类似事项，导致重复答案和额外用量。应在进入Agent之前合并相同材料对的关联事项。

## 产物

平台根目录下 `runtime/replay/agent-four-types-20261031/`：

- `index.html`：测试回放，含原图、OCR、逐项结果与证据。
- `results.md`：模型逐项解释与警告，保持原始结论，不把人工审阅意见冒充API输出。
- `progress.json`：每组状态、延迟、模型轮次、工具轨迹和SDK用量。
- `group-N/local.json`：本轮重新执行的字段、本地检查和审核分级。
- `group-N/package.json`：实际发送的结构化材料包，不含作者答案。
- `group-N/result.json`：完整审核返回及本地证据回映。
- `group-N/session/`：调用预算和成功结果缓存。
- `group-N/annotation-after-review.json`：事后对照标签。
- `run.mjs`、`render.py`：运行与展示脚本。运行脚本使用排他创建避免覆盖旧结果，不能直接对同目录重复付费执行。

预览服务端口4182下 `agent-four-types-20261031/`。本轮只验证内容审核链路，不改变正式服务的外部API开关，不提交、不推送。

组18出现一次 submit_review 被拒，原因 cited_evidence_not_read；模型随后 get_evidence 补读并成功提交。说明证据读取约束实际生效。另一方面，配置maxTurns=8但SDK报告num_turns=11，预算参数与实际轮次存在差异。未新增付费请求排查，不能宣称最多8轮的硬限额已经验收；后续应核对SDK计数/执行语义，并增加宿主侧计数与终止策略。

本轮可以确认四类材料的Agent流程能够执行并发现组内差异，不能宣称四类准确率100%。授权差异的过度推断、未支持字段的误解、证据截断、重复事项和预算限制均需后续修正。没有使用这四组结果反复修改提示词后挑选最佳输出。
