2026-10-23修正：前台与接口统一按核验功能开放，不再提供用户机构身份选项或按身份限制功能；下述2026-10-22机构场景表仅保留为内部需求研究记录。新请求不含role，购方/销方等材料语义角色不变。

本轮仅推进 `add-image-documents`，按用户与导师确认的方案更新四份OpenSpec后，分规则、解析、前端三个子agent并行实现，主agent完成模型编排、HTTP、解释预算与综合验证。未提交、推送、合并、切换分支或归档，也未清理原有文件。2.1工作包和模型资产未改写。

## 已接通的流程

`#/image/documents` 已有真实 VERITAS 工作台：核验功能、地区、材料类型、批量选择、核心文件、显式关联依据、任务状态、页图与疑似区域、提取字段、单份规则、围绕核心的跨材料结果和未覆盖项。

同批次流程：本地图片/PDF/Word解析 → MIRROR → SEED → OCR → 单份规则 → 有确认依据的核心关系比较。独立阶段失败不会跳过可用规则。研究模型使用固定权重/源码和既有隔离环境；阶段前查询当前GPU，不套旧卡号。首次实现采用批次子进程加载，尚非模型常驻服务。

辅助材料不是自动可信事实。同名、同额、同批次均不自动形成关系。用户的显式确认由后端验证引用和已提取角色，记录为本地用户声明；需要同金额/同日期事件/同张发票时分别确认口径。完整付款/红蓝票集合在规则内核可按显式集合计算，工作台尚未提供集合编辑器。

更多依据见[规则与场景](target-review-rules.md)、[统一解析](material-parsing.md)、[开源skills与解释设计](review-prompt-research.md)。

## API与运行

既有 `POST /api/v1/image/documents` 新增三种action：`scenarios` 返回核验功能目录；`review` 接收文件并返回202和任务ID；`status` 返回200和任务当前/最终状态。OpenAPI同步更新。其他9个业务接口保留501，2.1页面未改动。

每批最多10文件，单文件12MiB、解码总量24MiB、JSON正文34MiB；批次最多20页参与模型/OCR，超出页明确未覆盖。单服务实例仅处理一批，忙时429。所有上传、派生页和结果存平台根 `runtime/reviews/<uuid>/`，不自动删除。源文件名不作为落盘路径。客户端无法提供任意服务器路径、已确认关系或API配置；服务端目录、Python和配置不作为静态资源开放。

```sh
cd /sdb/data_public/lvjiawen/aigc_platform
source runtime/activate.sh
cd project
npm run dev
# 本机浏览器：http://127.0.0.1:4173/#/image/documents
```

远程开发可通过已有SSH端口转发访问。此工作台尚未接入公共身份认证、访问权限、长期保留治理及生产队列，不应直接作为公网服务。服务重启后可按既有任务ID读取已落盘结果，页面暂不自动恢复任务ID。

`options.runModels:false` 仅关闭MIRROR/SEED，仍运行OCR与规则；`options.renderWord:false` 可仅提取Word结构文字，视觉未运行。DOCX转换先预检宏/外部关系等，使用独立本地profile；旧DOC暂需转DOCX/PDF。不把Word结构位置伪装成页图坐标。
