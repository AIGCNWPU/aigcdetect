# 2.3 中文材料辅助审核：地区、机构与执行度调研

版本：2026-10-26。查阅日期：2026-10-26（北京时间）。用途：为本地规则、材料组织、模型待审问题和验收用例提供依据。本文件是研究及实施设计，不能把表中所有审核点当成已经实现的规则。

## 1. 范围与使用方式

平台辅助审核人员整理证据、发现问题、提出补证事项，不代替税务登记系统、人口身份系统、财务审批流或机构负责人作最终处理。内部研究保留税务、公安、高校、企业财务等角色，以明确谁需要什么证据；前台仍按“发票核验、采购履约核验、收付款核对、报销材料核验、身份材料核对”等功能组织，不公开机构身份入口，不按身份隐藏功能。

“核心材料”是本次核验对象，不代表它天然正确；一份报销包可以将报销单设为核心，也可以将某张发票设为核心。“一般材料”是常规支持证据；“条件必需”必须由具体业务前提触发；“可选核验材料”是辅助消除疑点的证据，不应被平台误报为法定必须提交。下列清单同时包含**官方明示要求**和**本平台建议的核验输入**，每个场景分别标明。

本轮覆盖全国税票和采购的部分通用规则，北京、上海、西藏三地的公开差旅与身份服务样本，以及北京大学某中心、上海交通大学、西藏民族大学的特定制度。没有完成全国省市县、所有学校和所有公司的规则普查。不同地区的资料不能拼成一个全国强制清单。

## 2. 政策适用不是只选一个省份

每项核验至少记录：`审核目的、业务发生日期、凭证日期、申请受理地、单位制度适用范围、出差目的地、材料类别、业务主体类型、制度版本、来源网址、查阅日期、例外条件`。

当前前台上下文仅提供地区（未指定／北京／上海／西藏）和业务日期，不收集机构身份。这不足以自动匹配机关或高校制度。配套 `review-policy-catalog.json` 是后台研究索引：所有来源和场景均为 `autoApplicable: false`，可以按地区及功能筛选背景参考，不能据此直接判定政策已适用或已提供完整政策正文，更不能将后台研究角色变成前台身份选项。

例如，北京某中央单位人员去西藏出差：单位适用制度可能是中央机关制度，目的地住宿标准可能按西藏档位计算；不能因为目的地是西藏就直接适用西藏自治区机关内部报销办法。西藏民族大学公开制度引用自治区文件，但学校位于陕西，学校名称不能代替出发地或目的地。

## 3. 场景与材料清单

### T01 企业普通发票入账前核验

- **内部角色／目的**：企业财务、税务辅助审核；核对取得的发票是否与购方和交易资料一致。
- **核心材料**：待核验发票。
- **一般材料**：单位确认的开票信息、该笔交易的合同或订单。后两项是平台核验建议，不声称每次报销均依法必须提交合同。
- **条件必需／可选**：取得合并开票明细时提供明细；退款、冲红、重开时提供关联凭证；付款回单、验收单用于业务关联核对。
- **逐项审核**：发票抬头和购方税号是否与确认的购方一致；不能把销方税号误当购方；金额、税额、价税合计及行项目相符；零税率同一行不得出现非零数值税额；混合税率不能用一个行税率判断整票；冲红符号、单据编号、币种和期间需对应。
- **边界**：2017年第16号仅在其适用条件下使用 [S01、S02]；税号或金额匹配不构成官方真票查验。免税、0%、不征税、差额计税分别处理 [S03]。用户目标是“该发票是否正确”，故其他材料围绕它组织，不默认辅助材料彼此全比较。

### T02 企业所得税支出凭证与异常补证

- **内部角色／目的**：企业财务、涉税辅助审核；核验某项支出的证据链。
- **核心材料**：该笔支出对应的外部凭证或内部报销凭证。
- **一般材料**：合同协议、支出依据、付款证明；官方规定要求有关资料留存备查 [S04]。
- **条件必需**：因对方注销等特殊原因无法补换发票，官方规定的原因证明、合同协议、非现金付款证明是必备资料；运输、出入库和会计记录依具体事实补充。
- **逐项审核**：各材料主体和交易编号、支付方向、发生期间、金额口径一致；无票原因与合同主体能否对应；付款不能只凭截图标题，应提取到账/支付状态、交易号及实际金额。
- **边界**：平台先判断证据是否齐全，不能以“未附发票”直接否定所有支出；税前扣除条件、例外是否成立交由带来源的政策审查。发票报销、企业所得税扣除、增值税抵扣是不同审核目标。

### T03 纳税记录或完税证明一致性核验

- **内部角色／目的**：税务服务辅助审核或企业合规人员；核对证明所属主体、期间和相关缴税记录。
- **核心材料**：完税证明或个人所得税纳税记录。
- **一般材料**：申请主体资料、明确期间内的缴税或收入明细；委托代办时按办理要求提供授权及身份材料。
- **可选**：银行扣款记录、申报表、原开具渠道记录，作为补充证据。
- **逐项审核**：纳税主体、税种、所属期与缴款日期分开；各笔缴退税及合计不能混为收入金额；不能把无欠税证明解释为全期零收入。证明类型与所属期间对应。
- **边界**：2019年及以后个人所得税证明调整为纳税记录，不能机械要求旧文书名称 [S18]；此处不接管电子税务局登录和官方记录查询。上海开具指南存在不同证明类型，文书式不可直接充当记账或抵扣凭证 [S19]。

### G01 北京党政机关差旅材料辅助核验

- **内部角色／目的**：适用北京机关差旅制度单位的财务审核人员；核对一次公务出差报销。
- **核心材料**：差旅报销单，或者用户指定的一项住宿/交通票据。
- **一般材料**：出差审批、交通票据、实际报销的住宿发票；会议培训场景补通知、时间地点信息。材料组是平台实施模板，具体必需项应结合正式办法附件和单位细则确认。
- **可选**：公务卡支付记录、行程变更批准、接待单位费用承担说明。
- **逐项审核**：出差人、时间区间、出发及到达地点与批准任务相符；报销天数不重复；同一住宿期间不重复入账；个人绕行、无票、超标准等触发例外审查。
- **边界**：使用北京机关制度及对应更新 [S06–S08]，不采用北京地理位置自动识别；中央单位、企业、高校有其他制度时不能强套。本文没有完成最新金额表核录，缺少政策配置时输出“标准待确认”，不是超标结论。

### G02 上海市级机关差旅及会议培训往返

- **内部角色／目的**：适用上海市级机关制度的财务审核；核对差旅和会议培训期间的费用归属。
- **核心材料**：差旅报销单。
- **一般材料**：出差审批、交通票据、住宿票据、会议培训通知；拟报项目与其证据一一对应。
- **条件必需／可选**：住家或边远地区无住宿票的情形，应补情况说明及部门领导批准；食宿由主办方承担时补费用承担信息。
- **逐项审核**：会议期间与往返期间分开；已经由主办方承担的项目不重复报；住宿票缺失不能直接推出所有交通及补助不准报；私家车、绕行、交通等级等按对应条款审查。
- **边界**：2025解答对2014办法执行作出具体说明 [S09、S10]，必须一起使用；这里只做有材料支持的时间/费用归属核查，不默认地方标准适用于上海所有公司和高校。

### G03 西藏自治区机关区内外差旅

- **内部角色／目的**：适用自治区机关制度的财务辅助审核；核对出差报销及偏远地区特殊凭据。
- **核心材料**：差旅报销单。
- **一般材料**：出差审批、交通及住宿凭据、用餐用车交款证明（发生相关安排时）。
- **条件必需／可选**：边远地区无住宿凭据、公务卡无法使用等按办法补审批；派车记录、区外行程、费用承担说明作为核查证据。
- **逐项审核**：区内/区外、时间和地点、是否单位派车；派车后市内交通补助的适用性；乡村无住宿凭据的批准条件；交款证明是补助证明还是报销凭据不能混淆。
- **边界**：2020办法明确区内外、季节与乡镇例外 [S11]。本文不摘取图片表格金额入代码；不得把地方规则等同“任何人去西藏出差的标准”。审批语义和地方细则缺失时转补证或人工确认。

### U01 北京大学前沿计算研究中心学生国内参会报销

- **内部角色／目的**：该中心师生及财务协助人员；核对国内参会支出材料。
- **核心材料**：报销申请或会议注册费发票。
- **一般材料**：交通票据、住宿凭据、列明收费标准的会议通知、相关签字；普通机票电子发票需匹配订单中的行程、舱位、支付明细。
- **条件必需／可选**：付款记录按中心触发条件提供；个人延长行程需区分公务和私人费用。平台不把内部指导原样当全校要求。
- **逐项审核**：会议名称与日期、参会人、收费项目、发票抬头、主办/承办收费主体；与普通出差票据的日期及支付重复检查；个人段与公务段分离。
- **边界**：公开页面明示仅供中心学生使用，部分依据只在校内IP可访问 [S15]。本轮不读取校内页面，不宣称已覆盖北京大学所有科研报销。

### U02 上海交通大学采购合同与结算核验

- **内部角色／目的**：学校采购、资产和财务辅助审核；核对设备或服务合同履约付款。
- **核心材料**：采购合同；若任务为某张发票核验，则发票为核心，合同为辅助。
- **一般材料**：发票、验收凭证、付款申请；采购文件及成交结果用于验证合同主要条款。
- **条件必需／可选**：预付款、分期、质量保证金、合同变更时补相应条款和审批；资产登记、交付清单根据校内配套制度补充，不在本文统一设门槛。
- **逐项审核**：合同标的、规格数量、价格、验收标准、履约期限与采购结果是否相符；实际付款节点和验收状态；是否把尾款与总价混比。
- **边界**：依据该校公开合同管理办法 [S16]；本轮不把学校合同门槛固化成全国高校规则，也不以付款日在验收前直接判错，因为合同可能约定预付款。

### U03 西藏民族大学差旅及住宿明细核验

- **内部角色／目的**：学校财务和项目负责人；核对纳入学校预算的差旅报销。
- **核心材料**：差旅报销单或住宿票据。
- **一般材料**：出差审批、交通和住宿凭据、会议培训相关材料；学校差旅平台订购与其他方式区分。
- **条件必需／可选**：非平台住宿发票未列住宿天数、数量、单价时，补酒店系统结算清单及相应印章信息；特殊事项按学校制度补批准材料。
- **逐项审核**：房晚、数量、单价、金额是否互相对应；人员和入住期间匹配；平台订单与发票是否重复；公私费用及费用承担方区分。
- **边界**：采用2025校内版本 [S17]，不默认沿用2021旧版；学校名称不代表差旅所在地。印章文字可参与名称比对，印章外观检测不证明其真实有效。

### C01 公司采购、验收和付款核对

- **内部角色／目的**：公司财务、采购或内审辅助人员；检查一笔采购是否具备付款及入账证据。
- **核心材料**：采购合同、付款申请或指定发票，根据目的三选一。
- **一般材料**：订单、发票、验收或入库凭证、付款回单；内控指引提供流程依据，不表示所有企业和所有小额采购均需相同纸质表单 [S05]。
- **条件必需／可选**：代收代付授权、退款、折扣、退货、分批交付、分期支付的证据；供应商主数据作为确认后的比较基准。
- **逐项审核**：合同方—销方—收款方角色关系，数量、单价、含税口径、货币、收货量、已付和应付的范围；集合确认完整后再加总；代理收款有授权不能直接认作错误。
- **边界**：依据企业适用制度和合同；公司自定交通住宿上限、审批权限及预算规则未提供时不推断。采购真实性、实际货物质量不能从材料一致直接证明。

### C02 小额零星支出与收款凭证核验

- **内部角色／目的**：企业财务；核对无法取得普通发票的特定小额零星支出证据。
- **核心材料**：收款凭证和内部凭证组成的指定证据组。
- **一般材料**：支出项目、收款方身份信息、金额、付款记录及业务用途。
- **可选**：服务完成确认、采购清单、收款方说明。
- **逐项审核**：凭证记载信息是否齐全、付款与收款方及项目一致、金额是否相符；替代凭证适用资格不能只从“金额小”推断。
- **边界**：2018年第28号对主体和起征点有条件 [S04]；本轮不设全国统一金额阈值。个体经营户作为收款方与企业所得税纳税人作为报销方的身份不同，应分别建模。

### P01 北京居民身份证换领材料预核验

- **内部角色／目的**：身份材料辅助审核；检查申请材料内部是否一致、是否缺相关证件。
- **核心材料**：待核对居民身份证及换领申请信息。
- **一般材料**：按照京籍换领公开指南提供原身份证；未满16周岁情形按指南增加监护人身份证。
- **可选**：涉及姓名变更或登记纠错时的相关证明，应按具体事项指南补充，不能把所有证明默认必需。
- **逐项审核**：姓名、号码、出生日期、性别、有效期及监护角色分离；申请人和监护人不是同一字段，不因为号码不同报矛盾；身份证过期本身可以是换领原因，不能直接当伪造。
- **边界**：公开指南2025版本与2026线上服务说明均需结合办理渠道 [S12、S13]。现场指纹、人像和人口库核验不属于本平台材料审阅能力；线上条件涉及未取得的历史采集记录时输出待核实。

### P02 上海居住登记与住所证明核对

- **内部角色／目的**：居住登记材料辅助审核；检查申请人和住所证据的关联。
- **核心材料**：居住登记申请信息。
- **一般材料**：身份证或户口簿、对应住所证明；租住、产权住房、集体宿舍分别选取证明，不把所有分支叠加。
- **条件必需／可选**：住近亲属住房涉及亲属关系证明或承诺；未成年人代办的监护材料按办理分支补充。
- **逐项审核**：申请人和证件主体一致；住所地址与所选证明一致；租期覆盖申请的居住事实；房东、承租人、近亲属角色区分；备案证明与普通合同不可互相替代。
- **边界**：采用上海公安人口管理相关公开解答及事项指南 [S14]；不能把身份证户籍地址与现居地址不同判为异常。官方动态事项页面部分正文抓取不完整，实施必需项前应复核当期清单。

### P03 西藏居住证申领证据分支核验

- **内部角色／目的**：居住证申领材料辅助审核；检查身份与某一合法资格分支的证明。
- **核心材料**：居住证申领表。
- **一般材料**：身份证及就业、住所、连续就读三个条件之一的证明。
- **条件必需／可选**：代办时委托人与代办人证件；居住登记卡和期间信息用于核对登记条件；就业分支用劳动合同/证明，就读分支用学生证/学校证明，住所分支用相应住房证明。
- **逐项审核**：正确处理“之一”，避免要求三套材料；各文件姓名、身份号码、所属单位/学校、住所、日期范围；登记时间与实际居住条件不能只从合同签署日推断。
- **边界**：西藏自治区2023公布办法 [S20]；全国条例仅为上位框架，不能拿上海租赁备案材料清单替代西藏具体受理要求。户籍系统记录、实际就业及实际居住仍需受理方核验。

### 4.1 零税率的安全执行边界

将税率表示保存为 `numeric_rate / exempt / non_taxable / differential_or_placeholder / unreadable`，不能统一替换成数值0。仅当**同一行、明确数值0%、明确对应的非零数值税额、解析无歧义**时输出内部算术矛盾。免税发票在税率栏选免税有官方依据 [S03]，但免税、零税率、不征税的法律含义不能混同。

普通税率行计算还需确认金额是含税还是不含税、行是否完整、折扣行归属及舍入方式。存在多税率时不得以单一行税率推整票税额。差额计税、免税占位符和看不清的税率转待核验，不能当0或自动确定税务违法。2026增值税法已施行 [S21]；历史业务不能自动应用今天的优惠规则。

### 4.2 材料关系与扩展复杂度

围绕核心材料建立可解释的关系边：同一交易、同一主体、同一报销任务、同一完整结算集合。关系需要编号、明确角色、用户确认或可靠证据，不靠姓名/金额恰好相同自动认定。每张辅助材料只执行目的所需的有限比较；需要跨辅助材料的矛盾检查时，为具体事项显式添加关系，不枚举所有二元、三元组合。

## 5. 执行度、覆盖率和分流建议

### 5.1 参考论文与能借用的部分

1. Geifman、El-Yaniv，**SelectiveNet: A Deep Neural Network with an Integrated Reject Option**，ICML 2019。论文研究选择性预测及风险—覆盖权衡 [R01]。本项目借用“证据不充分时允许不作自动结论、同时衡量自动处理覆盖和错误”的思想；没有训练Selectivenet，也没有获得论文的统计保证。
2. Breck等，**Data Validation for Machine Learning**，MLSys 2019。论文介绍面向生产机器学习的数据验证与异常发现 [R02]。本项目借用模式约束、输入质量与异常分开监控的工程思路；不是用OCR分数推导文件真伪概率。

以下分级、公式及门控是本项目设计建议，并非论文原有的财务审核标准。

### 5.2 不用一个百分数混合所有问题

对每个审核事项记录五个维度：

- **适用性**：已确认适用／不适用／政策或场景待确认。
- **输入证据**：字段齐全且可追溯／识别有歧义／材料缺失。
- **关系和口径**：同主体、同交易、同范围、同期间、同币种已确认／未确认。
- **规则能力**：确定性规则可覆盖／仅部分覆盖／需要语义或外部政策。
- **执行结果**：通过／明确异常／待语义核查／待补证／不适用／执行失败。

建议等级：A＝前提齐全且可执行确定性结论；B＝部分可核但仍有语义或范围待确认；C＝缺证或识别质量不足；U＝本地未覆盖/政策未配置。A不表示整份材料真实；B/C/U也不表示异常。执行结果与等级必须分别展示和保存。

OCR阈值仅是工程门槛；没有用独立中文样本校准前，不得标成“99%正确”。硬门控不能通过平均分掩盖：缺核心金额来源、关系不明、制度日期不适用时，其他字段再清晰也不能给A。

### 5.3 评价的分母和验收集

| 指标 | 定义及用途 |
| --- | --- |
| 本地自动结论覆盖 | 有人工确认审核目标的适用事项中，本地给出确定结论的事项数／全部适用事项数；必须把未覆盖能力计入分母 |
| 执行成功率 | 成功运行的规则实例／实际尝试运行的规则实例；只说明运行，不说明正确 |
| 选择性错误率 | 人工金标中，本地已接受自动结论但错误的事项／全部已接受自动结论事项；样本少时同时报样本数和区间 |
| 异常精确率和召回率 | 分别控制乱报和漏报；按场景、地区、材料类型分组，不只报一个总分 |
| 正确拒判/转交率 | 应补证或需语义事项是否被正确转交；“全部拒判”不能因错误少而算优秀 |
| 证据可追溯率 | 每项结论能否回到原页及字段/段落；跨文件结论必须有双方证据 |
| 模型调用率与成本 | 任务调用数、输入/输出量、缓存命中、每个完成事项成本；本地规则调用不混入云成本 |
| 脱敏影响 | 同一组有授权评测材料在原信息/脱敏模式下，正确结论、转交及引用保留情况的差异 |

使用CrossCred时按材料组和同源模板隔离开发与留出集，先复核其文字异常解释和比较前提；补合法的分期付款、代付、迁址、免税、多税率、无票批准等正常对照。FCTM可做定位验证，不能用于证明本地税务规则准确。受控合成样本用于门控和边界回归，不代替真实业务评测。当前没有本轮独立金标结果，不能填入估计准确率。

### 5.4 交给大模型的事项

本地已确定的简单算术/格式错误直接生成带依据的说明；对“已覆盖且检查通过”的事项不付费重复核验。字段清晰但语义、例外或政策适用不明确的，发送结构化证据包；缺页、OCR读不清、关系未确认的，先重识别或补证，不以模型猜测代替证据。

证据包建议包含：审核目的和背景、核心材料ID、各辅助材料关系、地区/单位制度及业务日期、允许发送的原文片段、字段及位置、已执行规则和结果、尚待判断的问题、已查证政策及生效范围、脱敏删去了哪些上下文、预期返回结构。最新政策不应靠模型记忆；未提供可靠来源时要求返回政策待核实，不能伪造已查政策。

建议返回字段：`事项ID、结论（合理/不合理/证据不足）、严重程度、简洁解释、证据引用ID、适用政策引用ID、需补材料、建议处理`。无论合理与否都给出针对问题的理由；不合理结论须醒目标明具体冲突，不堆砌泛泛免责声明。模型不能改变本地证据事实，新增语义判断与确定性规则结论分别保留。

原信息核查与脱敏核查两种模式应共享本地规则结果，仅改变外发证据。脱敏使用同一任务内一致的主体代号，保留角色、关系和必要单位/金额语义；删减后不能支持的事项明确转证据不足。国家秘密或组织制度禁止外发的材料不是点选“不脱敏”即可发送云端，应保持本地/指定私有模型处理；这是处理边界，不应在每条结果中重复堆免责声明。

## 6. 覆盖缺口与下一批规则建议

**优先可落地**：同一发票行0%与非零税额矛盾；正确区分购销方的企业税号要求；发票算术/中文大小写；在明确关系和范围下的金额、期间和身份字段比较；规则覆盖与原因码；按事项选择性转交。

**必须先补数据和适用配置**：各地住宿限额与旺季、交通职级、学校经费制度、公司报销制度；小额零星起征点及特殊发票税目；报销审批权限；身份证历史区划、租赁备案状态；所有依赖官方实时数据库的真伪/资格查询。

**无法由本轮文字规则保证**：票据真实开具状态、实际交易发生、实际居住/在职、印章和签名真实性、实物交付质量、证件现场人证一致。图像检测线索与内容核验可以合并展示，但不相互替代。

新增规则前应填写：来源、业务日期范围、单位和地区范围、前置字段、失败原因、例外、不可判条件、至少一个正例、一个异常例和一个合理例外。来源页面无明确生效日时保留“未核实”，不能将网页发布日期冒充法规施行日。研究清单需经目标机构确认后才能成为该机构的正式材料要求。
