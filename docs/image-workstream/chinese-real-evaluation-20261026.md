# 真实中文材料与大模型调用验收

日期：2026-10-26。本次使用已存在的中文数据原图，实际运行OCR、本地规则、MIRROR、SEED和DeepSeek官方API。**运行成功与业务效果通过分开报告：真实调用已完成，但当前效果尚不能判为业务验收通过。** 本轮没有下载新数据，没有修改历史原图、原标注或旧实验记录。

全国制度研究另见[31地总索引](national-review-research-20261026.md)。本文是开发诊断小样本，不是独立盲测、总体准确率或上线效果承诺。

## 2. OCR与本地规则实际效果

模型为本机PP-OCRv6 medium，CPU运行；16/16张执行成功。这只是识别任务完成，尚无逐字人工转录，**不报告字符准确率**。

| 组 | 文件数 | 结构字段数 | 原生关联边 | 主要诊断 |
|---|---:|---:|---:|---|
| 0 完税材料 | 2 | 0 | 0 | 有OCR文本，但当前字段模板未覆盖 |
| 1 承诺/账户材料 | 3 | 0 | 0 | 不能把多账户直接判错 |
| 34 增值税发票 | 5 | 15 | 0 | 未抽齐金额/税额等关键口径，票号和合计核验均需信息 |
| 43 户口材料 | 2 | 2 | 0 | 少量日期结构成功，不能据此认定身份关系正确 |
| 72 采购合同 | 2 | 0 | 0 | 合同语义与业务字段抽取不足 |
| 74 租赁合同 | 2 | 0 | 0 | 首付款、押金和租金关系未落入现有规则 |

合计17个字段，9/16份材料没有业务字段。6组原生关系边全部为0，故**自动跨文件关联未在本批样本中成功建立**。保留原生结果，没有偷偷注入编号、金额或人工关系来提高成绩。

单份本地检查共58项：18 PASS、40 NEI。18 PASS中11项仅为`scenario_applicability`适用性，7项为`displayed_calendar_date`日期检查；不等于18项财务核验成功。NEI包括16项机构制度、9项字段覆盖、5项适用性、5项价税合计、5项票号格式。本批没有形成确定内容冲突。规则级PASS比例不能当作文件正确率。

证据：`ocr.json`、`semantic-live/group-*-local.json`、`semantic-live/report.json`；单份与分组原生结果分别保留。

## 3. 实际大模型调用

使用生产适配器`runSemanticReview`与官方DeepSeek接口，模型别名`deepseek-flash`；没有mock、预置答案或失败重试。单请求超时90秒，批次硬上限8次，发起前落盘请求摘要，失败同样占预算。8次预算已用完，本轮不继续追加。

因为原生关系构建失败，本节明确单独设置“发布者同组候选材料语义诊断”，要求模型先验证共同标识，再核差异。没有造出已确认关联边。这样能够测API的理解能力，**不能冒充从上传到自动关联再审核的完整端到端成功**。本轮不测试政策解读，证据包政策引用为空，避免以地区制度推断样本文档真实性。

### 3.1 原图对照发现

- **发票：发现了问题却未明确告警。** 原文模式指出相同票据标识下的内容差异，并发现其中金额加税额不等于价税合计、另一张展示税率与税额不符。却仍仅输出需补充信息，确定问题被埋在解释中。应允许“已确认问题”和“其他未决事项”同时存在。
- **租赁合同：漏检。** 原图写明月租1700、押一付一、首付款含一月押金和租金，却为2400；本轮未抓住这一单份合同矛盾。模型还因输入遗漏地址而暗示原材料地址不全。
- **采购合同：能发现日期、金额等差异，但部分规格差异来自输入遗漏。** 同编号等关系需进一步核实，不能一律当作同一付款批次；原图规格实际一致，OCR缺字不能转写成原图差异。
- **承诺材料：不同账户不是天然错误。** 模型保留这一例外是正确的；但有把过滤后未输入的条款当作原材料缺失的倾向。

另一个代理实际查看8张原图并逐项复核8次响应，报告见[语义核验原图复核](chinese-semantic-audit-20261026.md)。这是开发代理复核，非独立领域专家标注；不据此输出精确率、召回率或4组“准确率”。

### 3.2 脱敏损失与成本

4个脱敏请求保留52个证据条目，原文为340个；条目减少约84.7%，不是精度下降84.7%。输入token从原文合计19,992降到脱敏7,432，减少约62.8%；但在字段抽取失败时，保守脱敏丢掉大量关键上下文，低成本调用也可能没有审核价值。

8次合计输入27,424 token、输出4,141 token、总计31,565；输入中缓存命中4,736、未命中22,688。按核查时官方Flash峰/谷价格估算约 **0.00590—0.01180美元**，不是已查询账单。逐次实际用量保存在`semantic-live/attempt-*-usage.json`。[DeepSeek官方价格表](https://api-docs.deepseek.com/quick_start/pricing/)

当前不能据此选择“总是原文”或“总是脱敏”。先改善本地字段覆盖和证据保真，令脱敏保持同一主体稳定代号、条款结构及数值口径；没有足够可核证据时应跳过API并明确补充事项。

## 4. MIRROR与SEED真实中文图像测试

执行前检查GPU占用，选择当时空闲的物理卡1，单卡顺序执行；没有直接沿用旧服务器卡号。两模型均严格加载，missing/unexpected为空。此次独立诊断执行次序为SEED后MIRROR，不是业务编排顺序验收。

| 样本 | MIRROR整图生成分数 | SEED篡改分数 | 与发布者mask的IoU | Dice |
|---|---:|---:|---:|---:|
| fctm-0 | 0.05897 | 0.97693 | 0.10881 | 0.19627 |
| fctm-4 | 0.07424 | 0.96927 | 0.05715 | 0.10812 |
| fctm-9 | 0.07398 | 0.99549 | 0.12587 | 0.22359 |
| 均值 | — | — | **0.09728** | **0.17599** |

SEED以0.5阈值对3个篡改变体均报警，但定位重合很低；不能把“3/3报警”表述为模型准确率100%。发布者GT为字段区域填充矩形，非逐字符像素精标；指标衡量与该发布区域标注的几何重合。未改变阈值以追求当前样本高分。

MIRROR检测整图AI生成，图像局部改字属于不同任务；低生成分数不能解释为“无篡改”或按篡改标签计算其错误率。两种分数均非经业务校准的造假概率。

证据：`fctm-seed/results.json`、`fctm-mirror/mirror.json`、GPU记录、mask/overlay、`fctm-pixel-metrics.json`。IoU=TP/(TP+FP+FN)，Dice=2TP/(2TP+FP+FN)，预测采用输出二值mask，GT非零白色前景，尺寸逐一相同，无插值配准。本批无真实负样本、独立模板和大规模标注，不报告FPR、AUC或泛化结论。

## 5. 复跑入口及工程验证

使用迁移激活入口设置`AIGC_PLATFORM_ROOT`；无需重建环境或下载权重。样本路径从冻结清单读取，不把原服务器绝对路径抄入文档。

- OCR：`scripts/image-validation/smoke_ocr.py`，指定本地OCR权重、冻结`ocr-manifest.json`及新的输出目录。
- 本地/构包：`node scripts/image-validation/evaluate-chinese-semantic.mjs "$AIGC_PLATFORM_ROOT" "$NEW_FROZEN_RUN"`；不带`--live`不会调用API。
- 真调用：`scripts/image-validation/launch_semantic_live.py`，通过现有服务端配置加载器仅在进程内使用凭据，输出文件不保存key。必须使用新冻结批次及新预算；不能把本批8次重复运行当作免费验证。
- 区域目录：`scripts/image-validation/build-national-research-index.py`从三个原始来源账本生成可分享的元数据索引。

本轮Node回归222项全部通过；项目检查、构建、HTTP冒烟通过；OpenSpec固定1.13.1，全部11个工作包严格校验通过。真实浏览器验证31地及未指定选项、选项状态、OpenAPI和桌面/移动显示，无页面异常；此浏览器检查不上传样本、不调用API。证据为`node-tests.log`、`check.log`、`build.log`、`smoke.log`、`openspec.log`及`browser-regions.json`。这些工程检查不消除上述真实数据问题。

## 6. 验收判断和下一步优先级

| 项目 | 结论 |
|---|---|
| 16张真实OCR、3张MIRROR/SEED运行 | 运行通过；内容准确率未建立 |
| 8次真实DeepSeek请求、预算、格式及证据引用校验 | 运行通过；业务判断效果未通过 |
| 本地覆盖及自动跨文件关系 | 覆盖不足；9份无字段，6组0关联 |
| 明确算术错误的用户警告 | 未通过：发现但未结构化告警 |
| OCR缺失与原文缺失的区分 | 未通过：至少3组出现不当转述 |
| 脱敏后上下文保真 | 未通过充分性验证；多数有效证据被丢失 |
| 篡改定位 | 本批区域重合低；不满足精确定位效果结论 |
| 政策理解与最新政策检索、权威验真 | 本轮未测 |
| 跨图像/PDF/Word自动全链路与负样本泛化 | 本轮未重新验收，既往记录不代替本轮 |

建议先修：①合同/承诺/户口及旧版票据字段抽取与置信度；②不依赖全局关系的单份金额矛盾；③按事项输出已确认问题和未决事项，确保警告不被NEI吞掉；④强制区分“输入未覆盖”与“原件缺失”；⑤保留关系的稳定脱敏；⑥扩充独立模板和真实负控，再测定位及跨文件关联。上述优化是后续任务，不将本次实测报告写成已经修好。
