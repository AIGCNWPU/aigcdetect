# 同批材料交叉核对规则设计

同一批次内的所有材料都参与候选匹配，包括 PDF 各页与用户更正后的字段。有共同字段即检查其可比较性；资料缺失或主体不明确时给出关联待确认，不能跳过后显示全部通过。本文件是首期规则设计依据，规则实现与验收仍归 `add-image-documents`。

## 材料与字段范围

首期按身份证、传统增值税发票、数电发票、普通收据、证明材料五类覆盖；同批可包含多个主体与交易。证明材料先提取姓名、证号、机构、业务号、日期、金额、地址等可识别字段，具体业务条件需要有来源的模板/知识库条目，不能假定任何证明均适用同一规则。

字段除值外保留语义，例如“出生日期/开票日期”“购买方/销售方”“登记地址/现住址”“应付/实付/含税/未税”。通用标签“姓名”“日期”“金额”本身不足以断言两字段应相等。

## 关联和执行顺序

1. 对每个文件/页进行分类、OCR、字段抽取；建立同批字段索引，候选索引不跨批越权检索。
2. 将号码、信用代码、订单/合同/发票号等强标识与姓名、地址、金额、日期等弱线索分开。共同文本、号码或候选别名均触发规则适用性检查。
3. 明确主体及其角色、交易、时间。强标识也要经过 OCR 可靠性检查；仅姓名相同只提出关联候选。记录关联由哪个独立证据或人工确认支持。
4. 先执行格式和精确比对，再做有来源的规范化/别名映射，再检查时间、数量、金额集合关系。外部语义 API 关闭时，无法通过本地规则解释的自由文本保留 NEI。
5. 无匹配、关联歧义、字段缺失、规则不适用和实际冲突分别记录。输出两侧字段值、页码、证据、规则版本及差异。

号码一位不同的材料不能被强标识索引遗漏：姓名、业务编号等弱线索产生候选；若缺少独立的同主体证据则提示关联不确定。若用户已明确两份属于同一人，可报告号码冲突。不能用被核对号码本身同时证明主体相同和号码冲突。

## 五类材料的十五种组合

以下规则均以字段清晰、角色相同或有明确对应关系为前提；缺少前提输出待复核/证据不足。组合覆盖不代表每对材料必须有可执行的相等检查。

| 编号 | 材料组合 | 核对内容 | 现实例外与处理 |
| --- | --- | --- | --- |
| C01 | 身份证 × 身份证 | 同主体号码、姓名、生日、登记性别；证件版本与有效期 | 正反面缺失只提示补件；换证和迁址不直接判假；多人同名不合并 |
| C02 | 身份证 × 增值税发票 | 发票明确的自然人购买方/经办人与证件字段 | 公司抬头不能与员工姓名比较；“个人”抬头不足以确认主体 |
| C03 | 身份证 × 数电发票 | 自然人抬头或明示身份标识与证件对应 | 与 C02 相同，票号结构按数电类型处理，不套旧票代码规则 |
| C04 | 身份证 × 收据 | 明示付款人/收款人及证号与证件对应 | 代付、代理收款须有关系证据，不自动要求付款人等于受益人 |
| C05 | 身份证 × 证明 | 证明对象姓名、证号、生日及在相应时点的年龄 | 签发人不是证明对象；登记地址与现住址区分，年龄按证明日期计算 |
| C06 | 增值税发票 × 增值税发票 | 同票标识字段一致、重复材料、同交易多票汇总 | 不同票号可为分次开票；红字/作废/重开按明确关联计算，未知状态不推断 |
| C07 | 增值税发票 × 数电发票 | 买卖双方、交易编号、商品及金额覆盖关系 | 跨票种重开需原票关系证据；不能仅金额相同认定重复报销 |
| C08 | 增值税发票 × 收据 | 销售方与收款方、购买方与付款方、交易及结算范围 | 开票不等于付款；定金、分期、手续费、含税口径需明确 |
| C09 | 增值税发票 × 证明 | 证明中的交易/采购、机构、票号、金额与明细 | 证明只覆盖部分采购时不能要求等于整票总额；无明细不补造 |
| C10 | 数电发票 × 数电发票 | 同票号多版本一致、交易关联、票据集合合计 | 红蓝票抵销须明确关系及符号；重复上传只计一次 |
| C11 | 数电发票 × 收据 | 交易、双方角色、实付与开票覆盖 | 多笔收据对一票、一笔款对多票分别建关系，未完整集合不判总额错 |
| C12 | 数电发票 × 证明 | 证明机构、业务号、金额与数电票内容 | 电子文件文本层和可见内容不一致单列问题，不宣称税务验真 |
| C13 | 收据 × 收据 | 同收据号字段一致、累计收款、退款及重复凭证 | 收据编号需加签发方作用域；不同机构同号不是同一收据 |
| C14 | 收据 × 证明 | 支付/收款证明与收据的对象、金额、日期范围 | 证明为累计到账时汇总对应收据；现金、转账方式差异仅在语义可比时检查 |
| C15 | 证明 × 证明 | 同对象同期间的事实字段、机构、业务编号与版本 | 不同生效期、不同事实命题可共存；同级来源冲突不得按多数票决定真值 |

## 多材料联合场景

| 编号 | 场景 | 规则与必要证据 |
| --- | --- | --- |
| G01 | 员工身份证＋公司抬头发票＋付款收据＋报销证明 | 区分员工、公司、销售方、代付人；凭报销关系核对，不把不同角色姓名当冲突 |
| G02 | 一项交易分期开票、多次付款 | 分别汇总开票净额和付款净额，仅在交易范围与集合完整性明确时对比应付；重复文件/同票多视图不累加 |
| G03 | 蓝票＋红票＋重开发票＋退款凭证 | 引用原票/交易关系，按符号与对应金额核算；缺原票时提示缺证而非直接失败 |
| G04 | 身份证换证、迁址、机构历史更名 | 按业务发生时点比较；号码编制地区不等于当前居住地；别名需知识库证据 |
| G05 | 同批两位同名者、多家同金额交易 | 建立多个候选关系；要求强标识或人工确认，不能合并后扩散错误 |
| G06 | 同一 PDF 混装证明与票据，另附图片复印件 | 页/片段分类，允许人工分组；识别重复来源，保留页面定位，避免同源重复增强证据 |
| G07 | OCR 把号码或小数点识别错 | 保存原文与候选，先复核识别；更正后生成字段版本并重算所有关联检查 |
| G08 | 内容正确但疑似被改，内容错误但无修改痕迹 | 视觉与内容两条独立结果，报告不把任一维度替换为整份真假结论 |

## 本材料规则与知识库

规则分为号码格式/校验、日期和有效期、票种字段、金额算术、跨字段一致性、跨材料关系六组。身份证号结构、日期、校验位及明示生日/性别对照按适用标准实现；地区查询缺历史覆盖时为 NEI。发票按票种区分号码/代码，不设“万能票号校验位”。金额使用十进制定点计算；明确币种、税口径、折扣、红字与舍入容差，缺明细时不进行完整合计判错。

知识库优先存储结构化规则、字段别名、材料模板、历史码表和经审核的关系证据；首期关系/字段索引即可支持本批材料，不强制引入向量数据库。文本检索只寻找候选规则与证据，不能把相似度转换成真实性概率。上传材料不自动变为可信知识库。

每条规则保存规则 ID/版本、适用类型、必需字段、主体/角色/时间前提、证据来源与原文位置、生效范围、执行函数、失败解释、缺证处理和测试案例。每条知识记录保存机构、版本、时效与审核状态。尚未取得依据的业务限制保持待配置，不让模型编造。

跨材料问题至少记录双方字段版本、关系证据、差异、规则版本和限制。FAIL 表示明确违反该条可执行规则；NEI 表示无法判定；系统异常属于 ERROR。未发现冲突只覆盖已比较字段，不能推断登记真实、交易发生或材料未篡改。

## 规则验收方式

C01–C15 每组至少覆盖一致、明确冲突、缺字段、关联歧义、角色/时间不可比五类用例；G01–G08 使用多份材料的整组用例。标注预期主体关系、所用规则、结果状态及两侧页码，不能只验证自然语言结论。

另测号码一位差、同名不同人、同号不同机构、同交易缺一张票、不同币种、重复截图、历史版本替换与 OCR 更正传播。任何匹配候选都可在覆盖记录中解释为何检查、为何暂不能检查。

### OCR 字段接入

`server/ocr-fields.js` 直接消费既有 `smoke_ocr.py` 的一个成功样本；类型由调用方明确提供。支持中文显式标签的同框冒号值、右侧唯一同行值，包括身份证号/姓名/生日、明确购买方/销售方、付款人/收款人、票号/交易号、开票日期和金额。不把证明中的泛称“姓名”猜成证明对象。

每个字段保留原始文字框、标签框、区域编号、最小识别分数、完整 OCR 指纹和抽取版本；整行框标为 `ocr_region`，不是字符级定位。同行多值、两个标签争用一个值、重复字段均保留复核；不跨行拼接或补造值。只对明确 `CNY`/`人民币` 前缀进行金额值规范化；`¥`、缺币种、异常数字保留原文，不推测币种。当前仅支持明确 `YYYY-MM-DD` 日期提取格式。

本地调用（样本序号从 0 开始，输出不得已存在）：

```sh
node scripts/image-validation/extract-ocr-material.mjs ocr-report.json 0 material-1 identity extracted.json
```

将输出的 `material` 加入内部批次 `materials` 后调用现有 `check-material-batch.mjs`；关联确认仍需独立可信上下文。该适配器只处理方向统一的单张图片 OCR；PDF 父文件/页码继续使用既有 PDF 链路，不能把渲染页样本冒充父 PDF。

实测已有真实 OCR 报告 `ocr-evidence-v2.json` 第 0 张（32 区域），输入兼容检查通过，但未命中中文显式标签，字段数为 0；输出为未覆盖，不能当作中文定位精度或核验通过。报告保存在 `tmp/image-workspace/reports/ocr-field-adapter-v1.json`。中文定位和 OCR→字段→跨材料冲突链路目前用合成夹具验证。

后续已增加身份号、中文大写金额、数电票实际版式、完整票据集合及真实中文 12 页验证，见[真实中文材料验证](chinese-validation.md)。`material-batch/0.3` 的通过项、缺证及未实现部分分别记录；完整业务规则尚未完成。
