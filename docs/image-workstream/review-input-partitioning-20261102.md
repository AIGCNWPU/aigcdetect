# 审核输入完整性与评测展示修订（2026-11-02）

## 正式流程

正式上传入口 `server/review-workflow.js` 改用 `planSemanticReview` 和 `runPlannedSemanticReview`，实现位于 `src/modules/image/documents/server/semantic-review.js`。版本为 material-semantic-review/1.5。

1. 完整编目可发送字段与正文，继续应用现有隐私过滤及识别质量门槛。脱敏过滤和低识别质量不等于容量丢失。
2. 常规材料总文字不超过12000字符、证据不超过512条时保留一次完整审核。
3. 超出容量按审核事项分批，材料交错排列；超过1600字符的文字块分片并记录原证据编号和字符偏移。每批不超过12000字符和512条证据，最后一份文件不再被前面的文件挤掉。
4. 最大16批，超过上限在调用前停止，不静默省略。分批计划持久化，改变同任务计划会被拒绝；每批沿用排他预算和已校验缓存，失败即停止，不自动重试。16批是会话上限，不是HTTP次数；SDK单会话原有工具/轮次预算继续生效。
5. 全部片段完成后合并明确问题及引用；分段信息不足结论不作为材料缺失发布。不把片段都未发现问题等同于全文通过。长文件跨片段语义尚未新增全局二次汇总，状态保持部分完成，不虚构全文结论。
6. 旧调用者若提交带容量截断标记的输入，会在调用前得到 input_requires_partitioning；模型回复中的输入截断等内部诊断不得成为材料告警，校验失败后保留本地结果。

字符容量仅限制证据正文，并非精确token计数；模型会话原有输出、工具和超时限制仍适用。此改动防止已知的顺序截断及处理告警外泄，不表示能保证任意模型永不生成不当解释。

## 用户界面

评测列名为生成模型、智鉴、方法1、方法2、方法3；删除介绍句、本地实测标签和排序说明。八行原始数值保持不变，实际行最大值继续加粗。内部映射依次为 DDA-H＋、PGC、PROBE、SAFE。
