## 建议汇报主线

本阶段把材料复核从“一次请求、直接生成结论”升级为“按审核步骤取证，再提交受校验的结论”。不更换整图和篡改模型，重点改善内容审核的执行过程。

1. 本地解析、字段与明确规则检查继续执行。
2. 将审核背景、待核对事项和许可的证据组织成结构化任务，保留脱敏/原文处理模式。
3. Agent 先加载审核指引，通过工具读取证据及已有本地结果，逐项分析。
4. 通过专用提交工具返回结构化结论，校验事项覆盖、引用是否合法、引用证据是否已经读取。
5. 最终仍交给原有展示层，按本文件与跨文件结果呈现，不把技术工具名暴露给产品用户。

Claude Agent SDK 是编排工具，版本固定为 0.3.314；底层模型仍是 DeepSeek，PDF 使用 deepseek-flash。不是把底层模型切换成 Claude。默认执行引擎改为 `claude-agent-sdk`，仍可通过服务端 `REVIEW_ENGINE=direct` 保留单次请求模式。

## PDF 的案例与结果

| 案例 | 已知正确核算 | PDF 记录的直接调用 | PDF 记录的 Agent |
| --- | --- | --- | --- |
| E01 合计错误 | 1530.00 + 198.90 = 1728.90，票面1788.90，多60.00 | 两轮均判合理，写出错误等式 | 两轮均指出60.00差额 |
| E02 两处错误 | 8 × 125 = 1000，行金额1040，多40；1040 + 135.20 = 1175.20，票面1275.20，多100 | 第一轮用未经证实的四舍五入/含税解释消除差异，第二轮错误等式均判成立 | 两轮均保留40.00与100.00两处异常 |

补充对照中，直接调用即使收到同样的完整审核 Skill，在这两个案例的两轮运行中仍判为合理。Agent 四次运行均调用了四类工具，使用5—6个模型轮次。

可以汇报：**这两个案例中，多轮取证复核保留了单次调用遗漏的金额矛盾，给出了正确算式和差额。**

不能据此汇报总体准确率、稳定消灭漏检或 Agent 必然优于直接调用。样本仅两张合成票；直接组是 Chat Completions、温度0、JSON模式，Agent 组使用 Anthropic兼容接口和SDK默认采样，执行方式与采样配置都不同。远端提交带来了PDF和代码测试，但未附这组对照的完整原始运行日志、成本台账及批量评测集。本地测试通过不等于重现上述真实模型结论。金额算术仍适合保留为本地确定性核验，不应全部交给模型猜算。

## 代码变化

| 文件 | 实际作用 |
| --- | --- |
| `review-agent.js` | SDK会话、四个专用工具、工具白名单、轮次/工具次数/超时限制、执行记录与token用量 |
| `review-skills.js` | 随代码交付的发票审核、通用材料审核指引，纳入缓存指纹 |
| `semantic-review.js` | 默认选择Agent或显式direct模式，保留一次会话预算、缓存、输出验证与本地证据回映；增加文字块证据引用 |
| `invoice-status-rules.js` | 识别票面“样张、作废、无效、禁止报销/入账”等明确声明，检查识别质量与来源定位 |
| `batch-engine.js`、`review-plan.js` | 将票面声明检查接入单文件及批次核验 |
| `local-runtime.js` | 新增服务端 `AIGC_PYTHON` 解释器覆盖选项 |
| `review-workflow.js` | 传递Agent适配器，接入现有审核编排 |
| `documents.js` | 师兄增加WARN中文标签及票面状态字段名；合并后保留我们后续完成的完整产品界面 |

四个工具分别是 `load_review_skill`、`get_evidence`、`get_local_findings`、`submit_review`。它们是平台限定的审核工具，不允许任意读文件、Shell执行、联网查税或调用不受控工具。代码强制先加载指引、读取所引用证据再提交；读取本地结果由指引要求和测试覆盖，不能说所有步骤都由同一种硬性状态机强制。

票面声明检查匹配完整分句，避免把公司名称、否定句、条件句中的“无效”误认成作废声明。例如“若有涂改，本票无效”不能直接等同于“本票无效”。WARN说明发现票面声明，不代表调用税务系统验证了官方状态。

## 本地衔接与成本

师兄指引原先要求跨材料关联已确认。本地保留用户最新要求：所有上传材料可围绕核心材料进行内容核对，但不得据此默认同一交易。已调整两份运行时指引以匹配本地语义任务范围。

默认预算是最多8个模型轮次、80次工具调用、90秒超时；预算单位改为一次Agent会话，不再等于一次API请求。失败不自动新开会话重试。按PDF记录，一次复核可能使用5—6轮模型调用，后续应单独统计费用、延迟和每个问题的检出收益。
