# CrossCred全量运行与本地规则验收 · 2026-10-27

## 范围与结论

本轮将CrossCred本机全部可用286张图片、78个发布者分组、21类材料纳入同一冻结清单。77组有图，已全部运行OCR、生产字段提取及按核心的本地核验；第69组两张源图完全缺失，不能实测。第27组缺1张，仅核验其余5张。**“全部纳入覆盖”不等于全部字段提取完毕、全部作者异常已确认或所有业务审核通过。**

最终286/286张匹配格式并产生结构字段，共1412字段、211个核心标识候选。77个有图分组均有比较输出：75组输出至少一项可见内容差异，1组（31）对应字段一致、未观察到作者所述差异，1组（77）关联比较仅NEI。四个候选存在识别复核前提。75组不是准确率，也不能解释为75组实际造假。

完整21类矩阵见[类型覆盖](crosscred-full-coverage-20261027.md)。现有44张OCR按相同原图SHA256和相同OCR模型资产SHA256复用，来源逐张记录；其余242张实际新运行本机PP-OCRv6 CPU。六个受限并发任务全部正常结束，286张均OCR成功，没有外部API、本地语言模型、MIRROR或SEED新调用。

## 补齐的类型与规则

新增`catalog-content-fields.js`，识别与字段依赖实际标题、明确标签、几何位置和段落边界，未按图片ID或分组号查答案。

| 类型 | 已实际运行的提取和比较 | 仍有的业务前提 |
|---|---|---|
| 无欠税证明 | 证明编号、纳税人/税号、出具单位、状态日期及明确证件号码；同编号或同税号内容核对 | 税号主体、管辖机关、状态有效时点与官方查询未验证；证件类型不明不套身份证校验 |
| 销售合同 | 合同号、甲乙方、签订日期、可提取总额、签章区委托代理人/法定代表人/电话/地址；同合同对应角色比较 | 不是完整条款法律解释，未提取行不用于强制合计；变更/补充协议需背景 |
| 小程序信息 | 由小程序名称与ID表头绑定同一行；同ID名称差异 | 更名和历史版本未确认，差异为WARN |
| 淘宝网店铺经营证明 | 店铺URL、账户主体、执照代码；同URL主体及代码比较 | 不访问店铺或官方登记，不确认经营权及转让历史 |
| 收入纳税明细 | 扣缴义务人、税号、税务机关、申报日期/所属期、收入/本期收入/申报税额；同扣缴标识核对 | 总览收入与本期收入分开，不将不同标签强行当同一字段；不推定零税额非法 |
| 商用办公室租赁合同 | 出租人、承租公司、签字代表分别绑定姓名/号码；租金与明确期限 | 第77组角色标签识别偏低，关联保持需复核，未假装完成内容判断 |

既有类型也经过全量扩展：账单详情/缴费详情、无分隔或分块户号姓名、到账负数、应缴金额与付款分开；承诺函账号条款允许换行及明确支付宝标签；完税证明支持标题拆分、No编号及地方旧编号，识别到更多格式但税表明细仍不完全覆盖。

## 关键修复与安全边界

- 完税标题不完整时，必须同时有明确税务表头和编号/完税结构证据，不用作者类别强制分类。
- 标签与值轻微相交、数值位于标签下方、姓名与身份标签同框、税号标签多行等有来源约束地提取；不修复原数字或补造OCR文字。
- 销售合同甲乙方只匹配标签边界，付款正文“乙方交货后”不再被当作姓名。
- 身份角色严格区分出租人/承租人/签字代表，扣缴义务人与纳税主体也分开；同名不是关联依据。
- 完整明细按集合比较，不因行序变化误报，缺列缺行保留NEI；日期格式不能唯一解析时不猜测。
- 弱识别候选仅限整体识别分数不低于0.75、值区域分数不低于0.95且源文字确有完整值的情况。保留原低分，标记`recognition_review_required`；比较全部保持NEI，不降低正常检查0.9门槛，不宣布同主体或同交易。
- 同出具机关、唯一原凭证号可在缺乏更强关系时作为补充候选，只核对原凭证对应内容，不伪造“同一证明编号”。没有全对排列组合。
