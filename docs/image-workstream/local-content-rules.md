本轮范围：真实中文目标数据的本地规则修复。执行结果以[中文目标数据复跑](local-content-rule-evaluation-20261026.md)为准。旧实验保留；本轮不调用外部API，不训练模型。

## 2. 正则的作用与输出结构

流程：OCR完整文字块→明确格式识别→字段标签/行列/段落提取→单份内容检查→核心标识候选→跨份内容比较→剩余含义转语义/人工。原图蓝字来自数据集；不是OCR按颜色选择，不是平台异常框。

正则用于文字形态与边界，例如身份号标签、账户邮件格式、`押X付Y`、`第一次…支付…元`和明确日期。它不替代十进制计算、日期日历、集合运算或主体/版本含义判断。不按作者答案、样本编号或期望金额查表。

字段记录key、role、value、version、confidence、source、extractionVersion及原OCR区域。提取置信度取涉及的标签/值/上下文OCR块分数的最小值；这是识别分数，不是真实性概率。行/段落来源仍是原OCR整框，不把正则字符偏移变成伪造字符坐标。

状态包括：格式未覆盖、标签/位置未匹配、OCR质量不足、多候选歧义、缺列/缺行、脱敏/截断、比较前提未知。重复候选保留，不能为了得到答案静默选一个；未抽到字段不描述成“原件没有”。

## 3. 格式与字段规则

| 格式 | 识别与字段 | 主要适用保护 |
|---|---|---|
| 传统增值税电子普通发票 | 明确票面标题；代码/号码/日期、购销方、商品、数量、单价、行金额/税率/税额、金额税额汇总、大小写合计 | 标题可同排拆块；按表头列和明细行读取；币种和计价口径明确。数电票使用原专门模板，不能套传统票号规则 |
| 承诺函 | 明确标题；姓名、原显示身份号、注册账户条款内邮箱集合、日期和承诺期间 | 邮箱只取有边界的账户清单，不抓联系人等全文任意邮箱；17位等异常号原样保留，另做格式核验 |
| 完税证明 | 明确标题；证明编号、纳税人名称/识别号、税务机关、填发日期及税表四列 | 税种、所属期间、入退库日期、实缴金额按行关联成JSON列集合；某列有缺块或多余字符时整列弃权，其他完整列仍可核验 |
| 常住人口登记卡 | 明确标题；姓名、身份号及已有生日字段 | 号码结构与显示姓名对应分开判断，不把同户或同名当真实同一人 |
| 购销/采购合同 | 明确标题；订单/合同编号、甲乙方、付款方、日期、商品及明确数量单价金额 | 角色不互换；只在单行唯一且口径明确时保留显式产品金额，不推算未知合同总额；规格漏提取不说成原文规格差异 |
| 房屋租赁合同 | 明确标题；出租人/承租人、各自身份号、地址、月租、押付月数、首付款、组成、调整条款 | 不混用双方身份；跨OCR块保留完整组成；未知抵扣优惠、额外费用、缺付款构成时停止套用简单公式 |

识别依据是独立明确标题，不是正文出现“请提交租赁合同”就认定当前文件为租赁合同。unknown声明可据标题推断并保留分类依据；已有用户声明不被随意替换。多页合并不继承单页“完整明细”结论。

## 4. 单份内容核验

1. **价税合计**：唯一、清晰、同币种的不含税金额+税额，对比价税合计，采用十进制定点和0.01元容差。缺字段返回NEI并说明未提取，不等于金额通过。
2. **税率税额**：同一明细行、同一税务口径下，比较行金额×显示税率与行税额；零税率与非零税额可直接发现矛盾。差额、免税、不征税等不简单套用普通公式。只检查票面显示关系，不判定法定适用税率。
3. **明细计算**：同一taxScope下数量×单价对比行金额；字段缺失或多候选不能拼错行。已明确完整明细时才合计对比汇总，不能把未识别行当0。
4. **大小写与日期/号码**：沿用已有确定性检查；日期PASS仅表示日历日期存在，号码格式PASS不表示官方登记有效。
5. **租赁组成**：明确月租×(押金月数+预付月数)对比注明包含押金和租金的首付。例：1700×(1+1)=3400，写2400则报告差额；没有明示组成或有未解释抵扣时返回NEI。

每项给规则名、状态、中文解释、原始reason码、实际字段与来源、必要计算和缺失前提。当前已用控制反例测试低质量、缺值、调整条款、同号不同票代码、重复原图、角色冲突等，不能只以目标正例数量验证。

## 5. 核心材料及跨文件规则

仅围绕核心材料建立显示标识索引：传统票代码+号码、数电票完整号码、同格式证明编号、合同/订单编号、显示身份号。相同姓名/金额不够建立这类候选；相同哈希重复上传不当作独立支持证据。

显示标识关系标为`observed_identifier_match`，信任语义为“观察到相同文字，不是官方身份或交易确认”。原有用户确认关系保留，二者不混淆。按同一字段/角色比较：

- 同票据标识：购买方、商品服务、数量、单价、金额、税额、合计等；不同代码的相同短票号不直接相连。
- 同证明编号：纳税人、机关、出具日期及税表集合。税表保留税种和值对应，不只比较孤立金额。
- 同合同/订单编号：交易日期、甲乙/付款方、金额及项目内容；差异可与分期、补充协议和更正版本并存，提示具体版本复核。
- 同显示身份号：对应姓名等内容；合同双方分别绑定，不因同合同把不同角色误合并。
- 承诺账户集合：输出交集、仅核心、仅辅助及集合数量差异。生产为WARN，表示差异确定；是否违反“完整且唯一列表”约束另问。作者完整列表口径仅在评测对照列单独统计。

候选与比较保持核心星状结构；当前每批文件/字段仍受系统预算限制。当核心缺某列时，保留核心NEI，在其**同一完整标识候选簇内**为该列选一份完整代表，线性补核其他辅助材料，标注`referenceComparison`和参考材料。既不补写核心未知值，也不枚举全组合，更不能把辅助一致当核心真实。

FAIL表示所声明的票面/内容一致性关系不成立，不能自动解释为犯罪、造假或已证实视觉篡改；WARN可表示明确差异而业务适用未决。对每个比较缺项，标明是哪份材料的哪个字段尚未提取。

## 6. 本地与语义衔接

本地算术、格式和集合已算完的事项不要求模型重新计算。事项分别组织为单份条款、标识差异的版本/适用前提、已确认关系的履约语义和机构政策，禁止一个全局NEI吞掉确定问题。

原文模式与脱敏模式继续分开。账户集合按**逐个账户稳定代号**替换，保持集合交集和差集结构；整列替换成一个不透明代号会损失关联，本轮已修正。身份、编号、地址等不外泄；自由文本无法可靠脱敏仍省略，必要信息不足则跳过调用并记录原因。只有日期与标点的包不再消耗语义调用额度。

提示词明确区分OCR遗漏、低质量过滤、脱敏省略和截断，不能把这些状态转成原件缺失；已发现有限矛盾时须填明确warning，并允许同时要求补充其他信息。本地确定FAIL/WARN在汇总中保留，语义未运行、失败或NEI不会取消它们。

本轮`scripts/image-validation/simulate-content-review.mjs`采用固定离线替身，仅验证事项、证据引用、模式及本地告警保留。输出标记simulated，**不是本地大模型推理，也不是API效果复测**。本轮API与实际模型推理次数均为0。

## 7. 仍未完成的边界

本轮是目标格式开发回归。全国/985高校研究尚未整体变成机构合规规则；未提供单位政策、有效版本和适用主体，制度项仍为未覆盖。未知格式、自由语义、文字遗漏、原件真实性与官方查验、全部286图/78组覆盖、独立泛化评估均不能据本轮通过。种子样本的作者标签与原图存在争议时并列记录，不以删除作者记录或制造规则异常追求满分。
